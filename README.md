# มูลค่ายาคืน (Returned Drug Value)

เว็บแอปของห้องยา **โรงพยาบาลปรางค์กู่** ที่มีหน้าที่เดียว — **แปลงยาที่ผู้ป่วยคืนมาให้เป็นตัวเลขเงิน**
แล้วสรุปเป็นตัวชี้วัด (KPI) ให้ผู้บริหารดูได้ทั้งปีงบประมาณ

เปิดเว็บ → พิมพ์ชื่อยา → ใส่จำนวน → กดบันทึก → เห็นมูลค่าที่ประหยัดได้สะสมทั้งปี พร้อมกราฟและปุ่มส่งออกไฟล์

---

## เว็บนี้ทำอะไรได้บ้าง

| หน้า | ทำอะไร |
|---|---|
| **บันทึก** | ค้นยาจาก 417 รายการของโรงพยาบาล **ค้นด้วยชื่อการค้าก็ได้** (Augmentin · Symbicort) กดเลือก ใส่จำนวน (รับทศนิยม) เลือกว่าใช้ต่อได้หรือต้องทำลาย แล้วกดบันทึกทั้งรอบทีเดียว · ยาที่ไม่มีในบัญชี รพ. พิมพ์ชื่อเองได้ |
| **ประวัติ** | ค้นด้วยชื่อยา · HN · ชื่อคนบันทึก · เลข Lot · กรอง 4 ช่วงเวลาหรือเลือกช่วงวันเอง · ดูเพิ่มทีละ 60 แถว · แก้/ลบ · **ถังขยะ กู้คืนได้** · **แบ่งกลุ่มด้วยสีจางตาม Lot** |
| **รายการ Lot** | ดูทีละรอบการบันทึก — วันที่ · ผู้บันทึก · จำนวนรายการ · มูลค่าใช้ต่อ/ทำลาย · **พิมพ์ใบสรุปแปะถุงยาได้** |
| **สรุป** | มูลค่าประหยัดสะสม · **เลือกปีงบย้อนหลังได้** · กราฟแท่ง 12 เดือน (ต.ค.→ก.ย.) · ยา 10 อันดับตามมูลค่า · **ยาที่ถูกคืนบ่อยที่สุด** · สัดส่วนแหล่งที่มา · ธีมสว่าง/เข้ม · ส่งออกไฟล์ |
| **จัดการราคา** | ใส่ราคาต่อหน่วย (4 ตำแหน่งทศนิยม) แก้หน่วยนับ · **นำเข้าราคาจากไฟล์ HIS ทีเดียว** · **ตีราคาย้อนหลังให้แถวเก่าที่มูลค่ายังเป็น 0** |
| **ตั้งค่า** | ชื่อห้องยา · แหล่งที่มาเริ่มต้น · ยาที่คืนบ่อย 6 ตัว · ธีมสว่าง/เข้ม · **เปิด/ปิดโหมดดูตัวอย่าง** |
| **เกี่ยวกับ** | ที่มาของเว็บ · เทคโนโลยีที่ใช้ · ผู้พัฒนา · เลขรุ่น — กดจากปุ่ม ℹ ที่มีอยู่ทุกหน้า |

### ยาที่คืนมาจาก รพ.สต. บอกได้ว่าแห่งไหน

เลือกแหล่งที่มาเป็น **รพ.สต.** แล้วจะมีช่องเลือกชื่อโผล่ขึ้นมา — อำเภอปรางค์กู่มี **13 แห่ง**

```
แหล่งที่มา   [OPD ทั่วไป] [OPD NCD] [ห้องยา IPD] [เยี่ยมบ้าน] [รพ.สต. ●]

รพ.สต. ต้นทาง                                          ยังไม่ได้เลือก
┌──────────────────────────────────────────────────┐
│ หนองเชียงทูน                                  ▾ │
└──────────────────────────────────────────────────┘
```

- ชื่อ รพ.สต. ติดไปกับทุกแถวที่บันทึก และโผล่ใน **ประวัติ · รายการ Lot · ใบสรุปที่พิมพ์ · ไฟล์ส่งออก**
- **แก้ย้อนหลังได้** จากหน้าต่างแก้ไขล็อต พร้อมเก็บร่องรอยว่าใครแก้จากอะไรเป็นอะไร เมื่อไร
- รายชื่ออยู่ในฐานข้อมูล ไม่ได้ฝังในโค้ด — เปิดแห่งใหม่หรือเปลี่ยนชื่อ แก้ได้โดยไม่ต้องขึ้นเว็บใหม่
- รหัสสถานพยาบาล · ตำบล · หมู่ที่ · แหล่งอ้างอิงทั้งหมด เก็บไว้ที่ [`docs/PCU-SITES.md`](docs/PCU-SITES.md)

### บรรทัดชื่อยาในผลค้นหา — อ่านได้แบบเดียวกับ ME-DRP

```
Chlortetracycline 10 mg/1 g (1%) ointment (Aureomycin®)
IV · หลอด

Hydrochlorothiazide (HCTZ) 25 mg tab        Morphine sulfate (MST) 10 mg tab (ER)
oral · เม็ด                                   oral · เม็ด
```

| ส่วน | สี | มีกี่ตัว |
|---|---|---|
| ชื่อสามัญ + ความแรง | ดำ + เทา | ทุกตัว |
| **ตัวย่อ `(HCTZ)`** | **ม่วง** | 127 |
| **ความเข้มข้น `(1%)`** | **ส้มอำพัน** | 19 |
| รูปแบบยา (`tab` `cap` `injection`) | เทาเข้ม | 409 |
| **รูปแบบการออกฤทธิ์ `(ER)` `(IR)`** | **แดงอมชมพู เอียง** | 12 |
| **ชื่อการค้า `(Augmentin®)`** | **เทลตัวหนา** | 43 |
| ทางให้ยา (`IV` `oral`) | เทา บรรทัดล่าง | 409 |

🚨 **`ER` กับ `IR` สำคัญที่สุด** — `Morphine 10 mg ER` ออกฤทธิ์ 12 ชั่วโมง ส่วนไม่มี ER ออกฤทธิ์ 4 ชั่วโมง
ในคลังมี `Sodium valproate 200 mg` ทั้ง ER และ IR ถ้าไม่แสดงจะเหมือนกันทุกตัวอักษร

**ยาสูตรผสมความแรงอยู่ในวงเล็บ** — `Ampicillin + Sulbactam (2 + 1 g)`
ไม่งั้นบรรทัดจะมีเครื่องหมาย `+` สองที่ แยกไม่ออกว่าตรงไหนชื่อยา ตรงไหนความแรง (มี 49 ตัว)

**🧩 v0.18.0.0 — ช่องค้นหากับหัวเว็บ เหลือตัวกลางตัวละตัว**

พี่กันไล่ดูหน้าจอมือถือจริงทั้งวันแล้วสั่งทีละจุด · ลงเอยที่การรื้อสองอย่างให้เหลือตัวเดียว

- **ช่องค้นหาทั้งเว็บเหมือนกันหมดแล้ว** — เดิม 8 ช่องวาดกันคนละแบบ บางช่องมีแว่นขยาย
  บางช่องไม่มี ปุ่มล้างคำค้นขนาดไม่เท่ากันสักช่อง · ตอนนี้ทุกช่องเรียกตัวกลางตัวเดียว
  ได้แว่นขยาย ปุ่มล้าง ป้ายบอกคำที่ใช้ค้น และการกันวรรณยุกต์โดนตัด มาครบเท่ากันทุกช่อง

- **ตัวอักษรในช่องค้นนั่งตรงกลางกรอบจริง ๆ แล้ว** — พี่กันชี้มาสามรอบว่า "มันอยู่บน ๆ ไป"
  ต้นเหตุคือช่องกรอกจัดตัวอักษรกึ่งกลางด้วยกลไกของตัวเอง โดยไม่สนระยะบรรทัดที่สั่ง
  ส่วนชั้นที่วาดตัวอักษรทับไว้เคารพระยะบรรทัด เส้นฐานสองชั้นจึงอยู่คนละที่

- **หัวเว็บสามหน้าตรงกันเป๊ะ** — พี่กันวัดด้วยตาแล้วจับได้ว่า "สองปุ่มนี้ ขยับตลอดทั้งสามหน้า"
  วัดจริงยืนยัน ปุ่มห่างขอบบน 11 / 18 / 15 จุด และปุ่มตั้งค่าหน้าสรุปล้นออกนอกขอบจอ
  ยกเป็นตัวกลางตัวเดียวแล้ว ค่าทุกตัวลอกจากหน้าบันทึกซึ่งเป็นหน้าที่ตรึงไว้แล้ว

- **ปุ่มปีงบไม่หายตอนรีเฟรชอีก** — เดิมรอรายชื่อปีจากเซิร์ฟเวอร์ ระหว่างรอมีปีเดียว
  แล้วตัววาดมีเงื่อนไข "น้อยกว่าสองปี ไม่ต้องแสดง" ปุ่มจึงหายทั้งแถวแล้วโผล่เองทีหลัง
  ตอนนี้คำนวณจากนาฬิกาเครื่องไว้ก่อน ไม่ต้องถามใคร

- **เลขรุ่นขึ้นใต้ชื่อเว็บหน้าบันทึก** เป็นสีเทลของเว็บ · หน้าประวัติกับหน้าสรุปมีบรรทัดรองแบบเดียวกัน

🚨 **ยาที่ยังไม่ชัวร์ ราคาถูกตั้งเป็น 0 ไว้โดยตั้งใจ** ไม่ใช่ลืมใส่
เพราะถ้าใส่ราคาที่อาจผิดลงไปแล้วมองข้าม ตัวเลข KPI จะผิดแบบเงียบ ๆ
แต่ถ้าเป็น 0 ระบบจะกันไม่ให้บันทึกยาตัวนั้นตั้งแต่หน้าบันทึกเลย

ทุกแถวมี **หมายเหตุบอกที่มา** ใต้ชื่อยา — `HIS 5 ส.ค. 69 · CefTRI-axone 1 g/vial`
พอเภสัชกรยืนยันเองจะเปลี่ยนเป็น `ยืนยันโดยเภสัชกร · <ชื่อ>`

💡 **ยาที่ราคา 1 บาท ไม่ใช่ความผิดพลาด** — เป็นยาที่โรงพยาบาลไม่ได้สต๊อก
เก็บรหัสยาไว้เผื่อผู้ป่วยส่งตัวมาจากที่อื่น (refer) แล้วถือยาตัวนั้นติดมาด้วย

### นำเข้าราคาจากไฟล์ HIS — สำหรับรอบถัดไปที่ HIS อัปเดตราคา

เข้าจากหน้าจัดการราคา กดปุ่ม **นำเข้าราคาจาก HIS** แล้วเลือกไฟล์ `รายการยา.XLS` ที่เอ็กซ์พอร์ตจาก HIS

ระบบจับคู่ชื่อยาให้อัตโนมัติ แล้วแยกเป็น 3 กลุ่มให้ตรวจทานก่อนบันทึก

| กลุ่ม | หมายความว่า | ผลกับไฟล์จริง |
|---|---|---|
| **มั่นใจ** | เจอตัวเดียว ความแรงตรง — ติ๊กให้ล่วงหน้า | 254 |
| **ต้องเลือก** | เจอหลายบรรทัด หรือความแรงไม่ตรง — กดเลือกเอง | 97 |
| **ไม่เจอ** | ไม่มีในไฟล์ — พิมพ์ราคาเองได้ | 66 |

🚨 **ระบบเสนอ เภสัชกรตัดสิน ไม่มีการนำเข้าอัตโนมัติทั้งดุ้น** เพราะราคาถูกแช่แข็งลงแถวตอนบันทึก
ถ้าจับคู่ผิดแล้วบันทึกไป ตัวเลข KPI จะผิดถาวร

**สิ่งที่ระบบทำให้เอง**
- คัด **ยาที่เลิกใช้แล้ว** (225 รายการ) และ **เวชภัณฑ์** (124 รายการ) ออกก่อนจับคู่
- รู้จัก **Tall Man Lettering** ที่ห้องยาใช้กันยาชื่อพ้อง (`CefTRI-axone` = Ceftriaxone)
- ตรวจ **ความแรงต้องตรง** ถ้าไม่ตรงจะไม่ยอมขึ้นว่ามั่นใจเด็ดขาด
- โชว์ราคาเดิมเทียบราคาใหม่ ถ้าเปลี่ยนขึ้นสีแดงเตือน

🔒 **ไฟล์ถูกอ่านในเครื่องเท่านั้น ไม่ถูกส่งขึ้นเซิร์ฟเวอร์** — ไฟล์มีบัญชียาทั้งโรงพยาบาล
สิ่งเดียวที่ส่งขึ้นไปคือรหัสยากับราคาของแถวที่ติ๊กยืนยันแล้ว

### โหมดดูตัวอย่าง — ดูหน้าตาเว็บตอนมีข้อมูลจริง

ตอนยังไม่ได้ใส่ราคายาจริง ตัวเลขทุกหน้าเป็น 0 หมด มองไม่ออกว่าใช้งานจริงจะเป็นยังไง
เปิดโหมดนี้จากหน้าตั้งค่า แล้วทุกหน้าจะเต็มไปด้วยข้อมูลสมมติทันที

- **ข้อมูลถูกสร้างในเบราว์เซอร์ล้วน ๆ ไม่เคยแตะฐานข้อมูลจริงแม้แต่แถวเดียว**
- สุ่มด้วยเมล็ดคงที่ → เปิดกี่ครั้งก็ได้ข้อมูลชุดเดิม เทียบหน้าจอกันได้
- มีแถบสีส้มเตือนค้างไว้ตลอดเวลาที่เปิด กันเผลอคิดว่าตัวเลขบนจอเป็นของจริง
- **ปุ่มบันทึกถูกปิด** และ **ระบบจะไม่เขียนอะไรลงเครื่องเลย** ร่างจริงที่กรอกค้างไว้ก่อนเปิดโหมดจะกลับมาครบตอนปิด

### หน้าบันทึกแบบคอม — ตรึงทุกอย่าง เลื่อนเฉพาะรายการ

หน้าบันทึกบนคอมล็อกความสูงเท่าหน้าจอ **ทั้งหน้าไม่เลื่อน**
ช่องกรอกยา · แถบยาที่คืนบ่อย · หัวคอลัมน์ · แผงขวา (แหล่งที่มา/วันที่/HN/ผู้บันทึก/ปุ่มบันทึก) ตรึงอยู่กับที่
มีแค่ **ในกรอบรายการ** ที่เลื่อนได้ — กรอกยาสิบกว่าตัวแล้วยังกดปุ่มบันทึกได้โดยไม่ต้องเลื่อนหา

หน้าประวัติแบบคอมก็ตรึงเหมือนกัน แต่ตรึงแค่ **แถบกรอง + หัวคอลัมน์** (ตัวหน้ายังเลื่อนได้ตามปกติ)

### ระบบล็อต — หัวใจของการทำงาน

**1 รอบกดบันทึก = 1 ล็อต** เหมือนล็อตสินค้าที่รับเข้าคลัง

- ระบบสร้าง **เลขล็อต** ให้เอง รูปแบบ `L690805-01` = ปี พ.ศ. 69 · เดือน 08 · วันที่ 05 · ล็อตที่ 01 ของวันนั้น
- ทุกล็อตต้องมี **ชื่อผู้บันทึก** (เลือกจากรายชื่อ 16 คนในห้องยา หรือพิมพ์ชื่อใหม่) — เลือกครั้งเดียวค้างไว้ทั้งเวร
- กดลองส่งใหม่หลังเน็ตหลุด ใช้เลขล็อตเดิม ไม่ออกเลขใหม่
- ค้นด้วยเลขล็อต หรือกรองดูเฉพาะล็อตเดียวได้

### หน้าบันทึกแบบคอม — กล่อง "Lot นี้"

แผงขวามีกล่องสรุปสิ่งที่กำลังจะบันทึก ให้ทวนก่อนกดปุ่ม

```
Lot นี้
รายการ  14 ตัว          ใช้ต่อ  11
                        ทำลาย   3
396 เม็ด · 14 แคปซูล · 2 กระบอก · และอีก 1
─────────────────────────────────────
เลข Lot                  L690806-04
```

- **แยกจำนวนตามหน่วยนับจริง** ไม่รวมข้ามหน่วยแล้วเขียนว่า "หน่วย" ลอย ๆ
  (เอาเม็ดไปบวกขวดบวกหลอด ได้ตัวเลขที่ไม่มีความหมาย)
- **เลข Lot ออกโดยฐานข้อมูลตอนกดบันทึก** เดาล่วงหน้าไม่ได้ เพราะเครื่องอื่นอาจกดแทรกก่อน
  ระหว่างกรอกจึงเขียนว่า "ระบบออกให้ตอนกดบันทึก" แล้วโชว์เลขจริงหลังบันทึกสำเร็จ
- **ปุ่มบันทึกถูกตรึงไว้ก้นแผง** จอเตี้ยแค่ไหนก็เห็น เนื้อหาด้านบนเลื่อนแทน

### การเข้าใช้งาน

มี **รหัสผ่านร่วมของห้องยา 1 ชั้น** — กรอกถูกครั้งเดียว เครื่องนั้นจำไว้ 30 วัน
หน้ากรอกรหัสมี **ปุ่มดวงตา** กดดูรหัสที่พิมพ์ได้ เผื่อพิมพ์ผิด
ออกจากระบบได้ที่ **ตั้งค่า → ออกจากระบบ** (ปุ่มโผล่เฉพาะตอนเว็บล็อกอยู่จริง)
รหัสตั้งเป็นค่าตั้งระบบชื่อ `MRV_PASSWORD` **ถ้าไม่ตั้ง เว็บจะไม่ล็อกเลย** (ตั้งใจให้เป็นแบบนี้ตอนรันในเครื่อง)

🚨 **ก่อนเปิดใช้จริงต้องตั้งเสมอ** ไม่งั้นใครมีลิงก์ก็เข้ามาลบข้อมูลได้ และ HN คือข้อมูลผู้ป่วย

### ตอนรันในเครื่อง — ข้ามหน้ากรอกรหัสได้

ตั้ง `MRV_DEV_OPEN=1` ใน `.env.local` แล้วเว็บที่รันในเครื่อง (`npm run dev`) จะเข้าได้เลย
ไม่ต้องพิมพ์รหัสทุกครั้งที่ทดสอบ

| | ในเครื่อง | เว็บจริงบน Cloudflare |
|---|---|---|
| ไม่ตั้ง | ถามรหัส | ถามรหัส |
| ตั้ง `MRV_DEV_OPEN=1` | **เข้าได้เลย** | ถามรหัส (ไม่เปลี่ยน) |

**ปลอดภัยเพราะต้องผ่านสองเงื่อนไขพร้อมกัน** — ต้องเป็นโหมดพัฒนา **และ** ต้องมีตัวแปรนี้
เว็บจริงถูก build เป็นโหมด production เสมอ ต่อให้ใครเผลอไปตั้งตัวแปรนี้บน Cloudflare ก็ไม่มีผลใด ๆ
และ `.env.local` อยู่ใน `.gitignore` จึงไม่มีทางติดขึ้น git

## หัวใจของแอป — ราคาถูกแช่แข็ง

ทุกครั้งที่กดบันทึก ระบบจะ **คัดลอกราคา ณ วันนั้นเก็บไว้ในแถวเลย** (`mr_return.unit_price`)
ไม่ได้เชื่อมไปอ่านราคาปัจจุบันตอนแสดงผล

แปลว่า **ถ้าราคายาเปลี่ยนกลางปี ตัวเลข KPI ย้อนหลังจะไม่ขยับ** — เหมือนใบเสร็จที่ออกไปแล้ว
ต่อให้ขึ้นราคาทีหลัง ยอดในใบเสร็จเก่าก็ไม่เปลี่ยน

จุดที่ต้องระวัง: **การแก้ไขรายการเก่า (PATCH) ห้ามแตะราคาเด็ดขาด** แก้ได้แค่จำนวนกับสถานะใช้ต่อ/ทำลาย

### ประตูหลังทางเดียว — ตีราคาย้อนหลัง

ถ้าเผลอบันทึกไปตอนยังไม่ได้ใส่ราคา แถวนั้นจะมูลค่า 0 ตลอดกาล
ทางแก้คือ **ตีราคาย้อนหลัง** ในหน้าจัดการราคา — ใส่ราคาแล้วระบบถามว่าจะเติมให้แถวเก่าไหม

🚨 **เติมเฉพาะแถวที่ราคาเป็น 0 เท่านั้น ไม่ทับแถวที่มีราคาอยู่แล้วเด็ดขาด**
เป็นการ "เติมของที่ยังว่าง" ไม่ใช่ "เขียนทับของเก่า" → กฎแช่ราคายังอยู่ครบ
มีช่อง `price_fixed_at` / `price_fixed_by` เก็บไว้เป็นหลักฐานว่าแถวไหนถูกตีราคาย้อนหลัง

**ทางกันไม่ให้เกิดตั้งแต่แรก:** ยาที่ยังไม่ใส่ราคา **กดเพิ่มเข้ารายการไม่ได้เลย**

## ก่อนขึ้นเว็บจริง เช็คสิ่งเหล่านี้

1. ตั้ง `SUPABASE_URL` และ `SUPABASE_SERVICE_ROLE_KEY` บน Cloudflare (Workers → Settings → Variables and Secrets)
2. 🚨 ตั้ง **`MRV_PASSWORD`** ด้วย ไม่งั้นเว็บจะเปิดโล่ง ใครมีลิงก์ก็เข้าได้
3. รันไฟล์ใน `scripts/` ตามลำดับ (`001` → `002` → `003` → `004` → `005`)
4. ใส่ราคายาที่คืนบ่อยจริงในหน้า **จัดการราคา** ก่อน ไม่งั้นตัวเลข KPI จะเป็นศูนย์
5. เลือกยาที่คืนบ่อย 6 ตัวในหน้าตั้งค่า
6. ล้างข้อมูลทดลองทิ้ง — `delete from mr_return; delete from mr_lot_seq;`
7. ชื่อโปรเจกต์ใน `wrangler.jsonc` ต้องตรงกับชื่อ Worker บน Cloudflare (`returndrug-pkh`)

**Build command บน Cloudflare = `npm run cf:build`** ไม่ใช่ `npm run build`
(`npm run build` สร้างไฟล์แบบ Next.js ปกติ ซึ่ง Workers รันไม่ได้)

## ที่มา

แปลงมาจากมอคอัปของ Claude Design (`Med Return App.dc.html`) แบบตรงตัวทุกจุด
สี ระยะห่าง ขนาดตัวอักษร โครง DOM เหมือนต้นฉบับหมด

จุดที่ต่างจากมอคอัปโดยตั้งใจ

1. **ปุ่มลบในหน้าประวัติมีหน้าต่างยืนยัน 1 ชั้น** — มอคอัปกดแล้วลบเลย ของจริงต้องยืนยันก่อน
2. **ตัดเลข "คงคลัง" ออก** — ในมอคอัปเป็นเลขสมมติ ของจริงไม่มีข้อมูลนั้น เหลือแค่หน่วยนับ
3. **ยาที่ยังไม่ใส่ราคายังโผล่ในผลค้นหา แต่ขึ้นป้ายเตือน**
4. **ช่องค้นในหน้าประวัติหน่วง 0.3 วินาที** เพราะยิงไปถามเซิร์ฟเวอร์ (ช่องค้นยาไม่หน่วง เพราะค้นในเครื่อง)
5. **มีหน้าจัดการราคา** ซึ่งมอคอัปไม่มี เพราะมอคอัปใช้ราคาสมมติที่ฝังไว้ในไฟล์
6. **หน้าบันทึกแบบคอมล็อกความสูงเท่าจอ** เลื่อนได้เฉพาะในกรอบรายการ — มอคอัปเลื่อนทั้งหน้า
7. **หน้าประวัติตรึงแถบกรองกับหัวคอลัมน์** — มอคอัปเลื่อนแล้วหัวตารางหายหมด
8. **หัวคอลัมน์กดเรียงได้ทุกคอลัมน์** ทั้งหน้าบันทึกและหน้าประวัติ
9. **มีท้ายเว็บ (เลขรุ่น + ลิขสิทธิ์)** และ **หน้าเกี่ยวกับ** ซึ่งมอคอัปไม่มี
10. **สวิตช์ คอม/มือถือ ย้ายขึ้นแถบบน** — มอคอัปลอยอยู่มุมล่างซ้าย ทับปุ่มในตาราง
    และโผล่เฉพาะเครื่องที่ **จอกว้าง ≥960 + มีเมาส์จริง** เครื่องสัมผัสล้วนไม่ขึ้น
11. **มีโหมดดูตัวอย่าง** ซึ่งมอคอัปมีในแบบของตัวเอง แต่ของนี่ถูกกั้นไม่ให้แตะข้อมูลจริงเด็ดขาด
