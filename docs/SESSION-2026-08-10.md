## 🐛 บั๊กที่ 1 — กดบันทึกราคาหลายตัวพร้อมกันไม่ได้ (พี่กันแจ้ง)

**อาการ:** กรอกราคาหลายตัวแล้วกดบันทึกทีเดียว ขึ้น "บันทึกราคาไม่สำเร็จ"
**กดทีละตัวได้ปกติ**

**วิธีหา:** เขียนสคริปต์ยิง API 3 เคส
```
1) ส่งเฉพาะแถวธรรมดา (3 ช่องเท่ากันหมด)         200 ✅
2) ส่งเฉพาะแถวที่มีช่องพิเศษ (6 ช่องเท่ากันหมด)  200 ✅
3) ส่งปนกัน 3 ช่อง + 6 ช่อง                      500 ❌ <<< เคสจริง
```

**ต้นเหตุ (จาก log เซิร์ฟเวอร์):**
```
null value in column "needs_check" of relation "mr_drug_price" violates not-null constraint
```

ตอนส่งหลายแถวพร้อมกัน PostgREST รวมรายชื่อช่องจากทุกแถวเป็นชุดเดียว
แถวไหนไม่มีช่องนั้นจะถูกเติม `NULL` ลงไป
แถวยาปกติไม่ได้ส่ง `needs_check`/`suggestions` มาด้วย จึงโดนเติม NULL
แต่สองช่องนี้เป็น `NOT NULL` → ตีกลับทั้งก้อน ทั้งที่ข้อมูลถูกต้องหมด

**ทางแก้ที่ไม่เลือก:** เติมค่าเริ่มต้นให้ทุกแถว
→ จะไปล้าง `note` กับ `suggestions` ของยาที่ผู้ใช้ไม่ได้ตั้งใจแตะ = **ข้อมูลหาย**

**ทางแก้ที่เลือก:** จัดกลุ่มแถวตาม "ชุดช่องที่เหมือนกัน" แล้ว upsert ทีละกลุ่ม
→ แถวไหนไม่ได้ส่งช่องไหนมา ช่องนั้นไม่ถูกแตะเลย · รองรับช่องใหม่ในอนาคตเองโดยไม่ต้องแก้ซ้ำ

**เทสหลังแก้:** กดทีเดียว 10 รายการ ปนกันทั้ง "รอกดเลือก" และ "ปกติ"
`saved: 10` · ธง `needs_check` เคลียร์ครบ · **หมายเหตุเดิมของตัวที่ไม่ได้แตะยังอยู่ครบ**

## 🐛 บั๊กที่ 2 — กล่อง "ไม่พบยาชื่อนี้" เด้งหลังกดเลือกสำเร็จ (พี่กันแจ้ง)

**อาการ:** กดเลือกยาแล้ว ยาเข้าช่องจำนวนถูกต้อง แต่กล่อง "ไม่พบยาชื่อนี้ ลองพิมพ์ชื่อสามัญ" ยังค้างอยู่

**ต้นเหตุ — แคลร์ทำเอง** ตอนเพิ่มการปิดรายการผลค้นหาอัตโนมัติ
```js
const picked  = !!st.pending && st.query === st.pending.name;
const results = (!picked && q.length >= 2) ? rankResults(...) : [];   // เลือกแล้ว → results = []
...
noResults: d.q.length >= 2 && d.results.length === 0                  // ← เห็น [] แล้วนึกว่าหาไม่เจอ
```

**แก้:** ส่ง `picked` ออกมาจาก derive แล้วเช็คเพิ่ม `noResults: !d.picked && ...`

**บทเรียน:** ค่าว่างมีได้หลายความหมาย — "ยังหาไม่เจอ" กับ "เลือกไปแล้ว" หน้าตาเหมือนกัน
ต้องแยกด้วยธงต่างหาก ไม่ใช่เดาจากความยาวของผลลัพธ์

## 🐛 บั๊กที่ 3 — ยาชื่อยาวทำชื่อการค้ากับความแรงหาย (พี่กันแจ้ง)

**อาการ:** ค้น `poly-oph` เจอยา แต่บรรทัดชื่อโดนตัดด้วยจุดไข่ปลา
ความแรงขาด และ **ชื่อการค้าที่ใช้ค้นหายทั้งอัน**

```
Gramicidin + Neomycin sulfate + Polymyxin b sulfate  25 + 2 + 5000 mcg/1 mL ...
                                                                            ↑ ตัดตรงนี้
```

**ต้นเหตุ:** บรรทัดชื่อใช้ `white-space:nowrap` + `text-overflow:ellipsis` บังคับอยู่บรรทัดเดียว

**แก้:** เปลี่ยนเป็น `overflow-wrap:anywhere` ให้ตกบรรทัดได้

**เหตุผลที่ยอมให้แถวสูงขึ้น:** ความแรงของตัวนี้คือ `25 + 2 + 5000` สามค่าคนละหน่วย
ถ้าโดนตัด เภสัชกรจะไม่รู้ว่าอีกสองตัวเป็นหน่วยอะไร — **เป็นข้อมูลความปลอดภัย ซ่อนไม่ได้**
แถวสูงขึ้นเฉพาะยาชื่อยาว ยาชื่อสั้นเท่าเดิม

## ✨ ชื่อการค้า — ทำตามแบบ ME-DRP

พี่กันชี้ให้ดู ME-DRP เป็นต้นแบบ
```tsx
{d.brand ? <span style={css("color:#0E7A66;font-weight:600;")}> ({hl(d.brand)})</span> : null}
```
วงเล็บ + สีเทลตัวหนา + ไฮไลต์คำค้นข้างใน + แสดงเฉพาะตัวที่มี

**ข้อมูลมีอยู่แล้วแต่ไม่เคยถูกใช้เลย** — `drugs.brand` มี 37 ตัวจาก 417
ไม่มีโค้ดตรงไหนหยิบมาใช้ (`catalog.js` / `drugName.js` / API ราคา ไม่เคย select มา)

**ที่ทำ**
- `lib/catalog.js` + `app/api/prices/route.js` — select และส่ง `brand` ออกมา
- แสดงในวงเล็บสีเทล `#2f7d5d` ตัวหนา **ทั้งผลค้นหาหน้าบันทึกและหน้าตั้งราคายา**
- **ค้นด้วยชื่อการค้าได้** — พิมพ์ `augmentin` เจอ Amoxicillin + Clavulanic acid ครบ 4 ความแรง
  (เภสัชกรจำชื่อการค้าได้ก่อนชื่อสามัญ · ME-DRP ค้นแบบนี้อยู่แล้ว)
  จัดอันดับให้ที่เจอในชื่อสามัญมาก่อนที่เจอในชื่อการค้า
- ไฮไลต์คำค้นในวงเล็บด้วย
