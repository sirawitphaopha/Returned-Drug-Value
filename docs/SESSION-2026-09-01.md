### ต้นเหตุ

`confirmRun` (ตัวสั่งทำงานของปุ่มยืนยัน) อยู่ใน `components/vals/history.js`
แต่ข้อ 3.62 (ก-8) ใส่ระบบข้ามการคำนวณค่าของหน้าที่ไม่ได้เปิดไว้

```js
history: sc === 'history',                    // ❌ อยู่หน้าบันทึก = ไม่คำนวณ = ไม่มี V.confirmRun
history: sc === 'history' || !!stt.confirm,   // ✅
```

**ป๊อปยืนยันถูกใช้ข้ามหน้า** — หน้าบันทึกใช้ทั้งตอนยืนยันก่อนส่ง และตอนลบรายการ
แต่ตัวสั่งทำงานอยู่ในไฟล์ของหน้าประวัติ พอไฟล์นั้นถูกข้าม **ปุ่มกลายเป็นปุ่มตาย**

🚨🔴 **โค้ดไม่ได้พัง มันแค่ไม่มีอะไรให้เรียก** จึงไม่มีสัญญาณเตือนใด ๆ เลย
ไม่มี error ไม่มี warning ไม่มีอะไรในคอนโซล — เป็นบั๊กที่เงียบที่สุดเท่าที่เจอมาในโปรเจกต์นี้

🚨 **ค่าที่ถูกใช้ข้ามหน้าห้ามอยู่ในไฟล์ที่ถูกข้ามการคำนวณได้**
ถ้าจำเป็นต้องอยู่ ต้องเติมเงื่อนไขให้คำนวณตอนของนั้นถูกใช้ด้วยเสมอ

| วิธีเทส | จับบั๊กนี้ได้ไหม |
|---|---|
| `setState` แล้วอ่าน state | ❌ ผ่านหมด |
| เรียก `app.save()` ตรง ๆ | ❌ ผ่าน (ข้ามป๊อปไปเลย) |
| **กดปุ่มจริงทีละขั้นเหมือนคนใช้** | ✅ **เจอ** |

⚠️ **CLAUDE.md ข้อ 3.62 เตือนเรื่องนี้ไว้เองแล้ว** ว่า *"ตรวจก่อนตัดทุกครั้งว่าไม่มีหน้าอื่น
ใช้ค่าข้ามไฟล์"* และเขียนว่าไล่ดูครบ 334 คีย์แล้ว — **แต่พลาดตัวนี้ไป**

**การไล่ดูด้วยตาไม่พอ ต้องเทสเส้นทางจริงทุกเส้นหลังตัดการคำนวณ**

🚨 **ชื่อปุ่มในป๊อปคือ "ยืนยันบันทึก" ไม่ใช่ "บันทึก"**
ตัวตรวจที่หาผิดชื่อจะรายงานว่า "ไม่ยิงอะไรเลย" ทั้งที่แก้ถูกแล้ว — เสียเวลาไล่ผิดทางไปหนึ่งรอบ
