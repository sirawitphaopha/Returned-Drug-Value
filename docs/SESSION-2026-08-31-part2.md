## 🔴 ทางที่เสนอไปแล้วพี่กันตีตก — บทเรียนสำคัญของรอบนี้

แคลร์เสนอ 3 ทาง แล้วแนะนำ **แบบ ก** คือให้ทุกหน้าต่างเห็นรายการชุดเดียวกัน
ทำมอคอัปให้ดูด้วย พี่กันดูแล้วจับได้ทันทีว่าพัง

> เดี๋ยวนะ ระบบอะไรเนี่ย แบบนี้ก็พังสิ ถ้าเปิด 100 แทป
> ถ้ากรอกมาพร้อมกันมันก็ขึ้นทั้งร้อยตัวสิ

**พี่กันถูก** — เปิด 3 หน้าต่างเพื่อกรอก 3 คนไข้พร้อมกัน (วิธีที่คนทำงานจริงใช้)
ยาจะไหลไปกองรวมเป็นล็อตเดียว **แย่กว่าของเดิมอีก** เพราะของเดิมอย่างน้อยแต่ละหน้าต่างยังโชว์ของตัวเอง

**แคลร์คิดแค่กรณี "เปิดสองแท็บโดยไม่ตั้งใจ" แต่ไม่ได้คิดกรณี "ตั้งใจเปิดหลายแท็บเพื่อกรอกแยกกัน"**

### และก่อนหน้านั้นยังพลาดเรื่องมอคอัปด้วย

แล้วยัง **ทำตัวใหม่เสร็จแต่ลืมส่งให้พี่กัน** พี่กันเลยกดตัวเก่าอยู่

## 1. ต้นตอที่แท้จริง

ไม่ได้อยู่ที่ "หน้าต่างไม่คุยกัน" แต่อยู่ที่ **ร่างที่กรอกค้างมีก้อนเดียวใช้ร่วมทั้งเครื่อง**

ทุกหน้าต่างเขียนลงกล่องใบเดียวกัน ตราบใดที่ยังใช้กล่องใบเดียว แก้ด้วยวิธีไหนก็ชนกันอยู่ดี

## 2. วิธีที่ใช้ — ร่างแยกรายหน้าต่าง

| ตัวช่วยใน `components/helpers.js` | ทำอะไร |
|---|---|
| `myTabId()` | รหัสประจำหน้าต่าง เก็บใน sessionStorage |
| `draftKeyOf(id)` | คีย์ร่างของหน้าต่างนั้น (`mrv.session.<รหัส>`) |
| `touchTab()` | บอกทะเบียนว่าหน้าต่างนี้ยังเปิดอยู่ (ทุก 15 วินาที) |
| `releaseTab()` | ปล่อยรหัสคืนก่อนหน้าหาย (ผูกกับ `pagehide`) |
| `tabAlive(id)` · `orphanDrafts()` | แยกร่างที่ยังมีเจ้าของ ออกจากร่างที่ไม่มี |

### 🔴🔴 บทเรียนหนัก — รีเฟรชกับทำสำเนาแท็บ แยกไม่ออก

ทั้งคู่คือ "มีรหัสเดิมใน sessionStorage และทะเบียนบอกว่ารหัสนั้นยังมีคนถืออยู่"

สิ่งที่แยกสองอย่างนี้ออกจากกันคือ **หน้าต่างที่กำลังจะรีเฟรชปล่อยรหัสคืนก่อนหายไป**
ส่วนต้นฉบับที่ถูกทำสำเนายังเปิดอยู่ ไม่ได้ปล่อยอะไร

ตอนแรกไม่มีการปล่อยคืน ทุกการรีเฟรชจึงได้รหัสใหม่ แล้วยาที่กรอกค้างกลายเป็นของ
หน้าต่างที่ไม่มีตัวตน = **กด F5 ทีของหายทั้งล็อต** — เทสจับได้ตั้งแต่รอบแรก
