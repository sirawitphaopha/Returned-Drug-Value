## 1. โปรเจกต์นี้คืออะไร ใครใช้

เว็บแอปของ **ห้องยาผู้ป่วยนอก โรงพยาบาลปรางค์กู่** แปลงยาที่ผู้ป่วยคืนมาเป็นตัวเลขเงิน
แล้วสรุปเป็นตัวชี้วัด (KPI) ทั้งปีงบประมาณให้ผู้บริหารดู

ผู้ใช้จริงคือ **เภสัชกรและเจ้าหน้าที่ห้องยา** ที่ยืนหน้าเคาน์เตอร์ ไม่ใช่คนสายไอที
เวลาออกแบบอะไรให้คิดถึงคนที่ต้องกรอกยาสิบกว่าตัวตอนผู้ป่วยรอ ไม่ใช่คนที่มีเวลาอ่านคู่มือ

## 2. พี่กันเป็นใคร ทำงานกับพี่กันยังไง

**รายละเอียดเต็มอยู่ใน `.claude/skills/working-with-gun/SKILL.md` — อ่านไฟล์นั้นให้จบก่อนเสมอ**
สรุปย่อสำหรับกันลืม

  ทำเว็บนี้คนเดียว เขียนโค้ดผ่านการสั่งงานแคลร์ล้วน ๆ
- **ห้ามคาดเดาว่าพี่กันรู้ศัพท์เทคนิค** อธิบายด้วยอนาล็อกทางยา/การแพทย์
- แคลร์เป็น**ผู้หญิง** ใช้ ค่ะ/นะคะ · เรียกผู้ใช้ว่า **พี่กัน** · **ห้ามใช้ ครับ/ผม**
- **ข้อความบนหน้าเว็บใช้ภาษาทางการ ไม่มี ค่ะ/นะคะ** และ **ห้ามมีเครื่องหมาย `?` ทุกที่**

## 3. กฎเฉพาะโปรเจกต์นี้

### เลขเวอร์ชัน — พี่กันมอบอิสระให้แคลร์ตัดสินเอง

สั่งไว้ **5 ส.ค. 2569**: *"โปรเจคนี้เราให้อิสระหมายเลขเวอร์ชั่นตามที่เธอเห้นสำควรเลย ซึ่งนี่คือกฎ"*

**ตั้งเลขเองได้เลย ไม่ต้องถาม** แต่ยังต้องทำครบทุกขั้น

| หลัก | ใช้เมื่อ |
|---|---|
| `W` (0.0.0.**X**) | แก้บั๊ก · ขัดหน้าตาเล็กน้อย |
| `Z` (0.0.**X**.0) | ฟีเจอร์ย่อย · ขัดหน้าตาชุดใหญ่ |
| `Y` (0.**X**.0.0) | ระบบใหม่ทั้งก้อน · รื้อโครง |
| `X` (**X**.0.0.0) | เปิดใช้จริงกับผู้ป่วย |

- รูปแบบ **4 ตำแหน่งเสมอ** `X.Y.Z.W`
- แก้ที่ **`components/helpers.js` (`APP_VERSION`) และ `package.json`** ต้องตรงกัน
- ก่อน bump รัน `git log --oneline -10` เช็คเลขที่ push จริง อย่าเชื่อเลขในโค้ด
- subject ของ commit ใส่ `vX.Y.Z.W:` **เฉพาะ commit ที่ bump จริง**

### push

- 🚨 **push ได้เฉพาะเมื่อพี่กันพิมพ์คำว่า "push" หรือ "พุช" ตรง ๆ เท่านั้น**
  "ทำต่อ / ทำเลย / เอาขึ้นเมน" **ไม่ใช่** การอนุญาต
- ทุกครั้งที่ push ต้องอัปเดต `README.md` + `CLAUDE.md` ให้ตรงก่อน
- commit message ละเอียดระดับไฟล์ต่อไฟล์
- push เสร็จ verify ด้วย `git rev-list --left-right --count origin/main...HEAD` ต้องได้ `0 0`
- push ขึ้น `main` ตรง ๆ ไม่ใช้ feature branch

### ไฟล์ .sql

สร้างเก็บไว้ใน `scripts/` เสมอ แล้ว**รันเองผ่าน Supabase MCP** ไม่ต้องให้พี่กันรัน

## 5. บทเรียนที่เคยพลาดในโปรเจกต์นี้ (ห้ามซ้ำ)

1. **ค้นข้อมูลในโค้ดก่อน อย่าไปค้นในฐานข้อมูล** — ตอนหารายชื่อคนในห้องยา แคลร์ไปนับจากตาราง
   ได้แค่ 4 ชื่อ พี่กันหงุดหงิด ของจริงอยู่ในไฟล์โค้ดของอีกโปรเจกต์ มี 16 ชื่อ
2. **จะดูโปรเจกต์อื่นให้โคลนจาก GitHub ลงมาใหม่** อย่าดูของที่ค้างในเครื่อง ไม่รู้ว่าเก่าแค่ไหน
3. **เว็บส่วนตัวกับเว็บที่ทำงานไม่เกี่ยวกัน** ห้ามเสนอโดเมน/บัญชีส่วนตัวมาใช้กับเว็บ รพ.
   (ยกเว้นเว็บที่ไม่เกี่ยวกับยา)
4. **`margin:0 auto` + พ่อเป็น flex = หน้าเว็บหดเงียบ ๆ** เคยทำหน้าเว็บหดจาก 1360 เหลือ 1013px
   ดู `CLAUDE.md` หัวข้อ 3.1
5. **อย่าเคลมว่าเสร็จ/ได้แล้ว จนกว่าจะเห็นกับตาจากการวัดจริงหรือภาพหน้าจอจริง**
6. **push ขึ้น GitHub ≠ เว็บจริงอัปเดตแล้ว** ต้องเช็ค Cloudflare build อีกชั้นแยกกัน

## 6. เรื่องความปลอดภัยที่ต้องรู้

- **repo นี้เปิดสาธารณะ** — ห้ามใส่กุญแจ รหัสผ่าน อีเมลจริง หรือข้อมูลผู้ป่วยลงไฟล์ใด ๆ ในนี้เด็ดขาด
- ค่าตั้งระบบทั้งหมดอยู่ใน `.env.local` (ไม่ถูก commit) และตั้งซ้ำบน Cloudflare
- ฐานข้อมูลเปิด RLS ทุกตารางโดยไม่มี policy = ปฏิเสธทุกคำขอจากภายนอก
  เข้าถึงได้ทางเดียวคือ API route ที่ใช้ `service_role` ฝั่งเซิร์ฟเวอร์
- **เบราว์เซอร์ต้องไม่เคยถือกุญแจฐานข้อมูล** ห้ามใส่ `NEXT_PUBLIC_` กับกุญแจ Supabase
- 🚨 ก่อนเปิดใช้จริงต้องตั้ง `MRV_PASSWORD` ไม่งั้นเว็บเปิดโล่ง และในเว็บมี HN ซึ่งเป็นข้อมูลผู้ป่วย
