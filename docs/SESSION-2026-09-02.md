## 🔴 บั๊กที่เจอระหว่างพิสูจน์ — ปิดบังทางเดียว อีกทางยังรั่ว

`apiFail` มี **สองทางออก**

```
เขียนลงบันทึกฝั่งเซิร์ฟเวอร์  ← ปิดบังแล้ว
ส่งข้อความกลับหาผู้ใช้        ← ยังรั่ว
```

ข้อความจากฐานที่มีตัวอักษรไทยปน **แม้ตัวเดียว** จะถูกส่งกลับทั้งดุ้น
พร้อมเลขผู้ป่วยที่ฐานใส่มาเอง ไปโผล่บนหน้าจอและในบันทึกของเบราว์เซอร์

```js
const msg = เป็นภาษาไทย(raw) ? maskHn(raw) : fallback;   // ต้องมี maskHn ตรงนี้ด้วย
```

🚨 **`scripts/mask-hn-test.mjs` จับข้อนี้ไม่ได้** เพราะตัวปิดบังทำงานถูกทุกเคส
สิ่งที่พลาดคือ **ลืมเรียก** · จึงต้องมี `scripts/api-fail-proof.mjs` แยกอีกตัว
ที่เรียก `apiFail` จริงแล้วดูทั้งสองทางออก

**ตัวอย่างโค้ดในสกิลกลางเขียนผิดแบบเดียวกัน** แก้ต้นฉบับให้แล้ว
ไม่งั้น DM Remission กับเว็บถัดไปลอกบั๊กไปใช้

## 🔑 วิธีทำให้เกิดข้อผิดพลาดจริงเพื่อดูบันทึก

กฎในสกิลบอกว่า *"ต้องเปิดดูบันทึกจริงหลังใส่ระบบเสมอ ไม่ใช่เชื่อว่าเขียนถูกแล้วจบ"*

**ปัญหาคือเข้า `catch` ไม่ได้เลย** — การตรวจข้อมูลฝั่ง API ดักคำขอที่จงใจส่งผิด
ไว้ก่อนถึงฐานทุกเส้นทาง (ซึ่งถูกแล้ว) ลองมา 7 เส้นทางโดนตีกลับด้วยข้อความไทยหมด

```
POST /api/returns  ชนิดข้อมูลผิด    → แหล่งที่มาไม่ถูกต้อง
PUT  /api/settings ชนิดข้อมูลผิด    → รายชื่อผู้บันทึกไม่ถูกต้อง
PATCH /api/lots/L999999-99         → ไม่พบล็อตนี้
PUT  /api/prices   รหัสยาเป็นข้อความ → รหัสยาไม่ถูกต้อง
```

**ต้องทำให้ฐานพังแทน** — ทำเซิร์ฟเวอร์เล็ก ๆ ที่ตอบข้อความแบบที่ PostgREST ส่งจริง
แล้วชี้ `SUPABASE_URL` มาที่ตัวนั้นชั่วคราว

```
ฐานส่งมา    duplicate key value violates unique constraint "mr_return_hn_idx" (hn)=(1482055) HN 14820
บันทึกเขียน  [returns.GET] duplicate key value violates unique constraint "mr_return_hn_idx" (HN ***) HN ***
ผู้ใช้เห็น    อ่านประวัติไม่สำเร็จ
```

เลขบรรทัด `route.js:1430:9` กับเลขรุ่น `0.16.3.0` ยังอ่านได้ตามเดิม ไม่โดนปิดบังผิดตัว

🚨 **ทำเสร็จต้องคืนค่าเดิมทันที** ทั้งปิดเซิร์ฟเวอร์ปลอมและเปิดเซิร์ฟเวอร์ทดสอบใหม่ด้วยค่าจริง
ลืมคืนแล้วรอบหน้าจะไล่บั๊กที่ไม่มีอยู่จริง

## ⚠️ กับดักของเครื่องนี้ที่เสียเวลาไปหลายรอบ

**heredoc ในเครื่องนี้กลืน backslash บางกรณี** — เขียนสคริปต์แก้ไฟล์แล้ว `\b` ในซอร์ส JS
กลายเป็นอักขระ backspace จริง (0x08) และ `\s` กลายเป็น `s` เปล่า ๆ
ทำให้ regex ในเอกสารพังโดยไม่มีอะไรเตือน

**วิธีเลี่ยง** — ใช้ `String.fromCharCode(92)` ประกอบ backslash เอง
หรือแก้ด้วยเลขบรรทัดแทนการค้นด้วยข้อความที่มี backslash
