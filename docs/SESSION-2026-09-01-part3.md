## 🔴 บั๊กหน้าไถล — ตอนรีเฟรชเข้ามาใหม่ยังลากได้

> *"ตอนรีเหรชหน้าเเล้วเข้ามา ตอนนี้คือเราขยับซ้ายขวาได้อยู่"*

**ต้นเหตุ** — ทุกอย่างที่ทำในรอบก่อน (ตัวดีดตำแหน่งเลื่อน · ตัวห้ามซูม · กฎ CSS)
**เช็คคลาส `.mrv-mobile` ก่อนทำงาน** แต่คลาสนั้นถูกใส่ใน `componentDidMount`
ซึ่งบนมือถือเกิดช้ากว่าหน้าโหลดเสร็จหลายวินาที — **ช่วงนั้นไม่มีการป้องกันอะไรเลย**

**แก้ 2 ชั้น**
- `_isNarrowNow()` — ด่านสำรองที่ใช้ความกว้างจอแทน ใช้ได้ตั้งแต่วินาทีแรก
- `_bindEarlyGuards()` — ผูกตัวดักตั้งแต่ `constructor` ไม่รอ `componentDidMount`

🚨 **กันการผูกซ้ำด้วยธง `_earlyBound`** React โหมดเข้มงวดสร้างคอมโพเนนต์สองรอบตอนพัฒนา

## 🔴 ยังซูมได้ทั้งที่ตั้ง touch-action ไปแล้ว

**ต้นเหตุ** — **`touch-action` ไม่สืบทอดลงไปยังลูก**
เบราว์เซอร์ดูค่าของ element ที่นิ้วแตะโดยตรง ใส่ที่ `html`/`body` อย่างเดียวจึงไม่พอ

**แก้** — `@media (max-width: 1179px) { html, body, body * { touch-action: pan-y !important } }`
พร้อม `text-size-adjust: 100%` กัน iOS ขยายตัวอักษรเองในกล่องแคบ

พี่กันสั่งเอง: *"ห้ามซูม เหมือนจุดที่ตรึงไว้ของปุ่มกดส่งยา เพราะแอปทั่วไป มันซูมไม่ได้ นี่นา"*
แคลร์ทักท้วงเรื่องคนสายตายาว (WCAG 1.4.4) พี่กันยืนยัน → ทำตาม

## หน้าตั้งค่ากับหน้าเกี่ยวกับ ต้องหน้าตาเดียวกัน

> *"ปุ่มเกี่ยวกับ กับตั้งค่า มันไม่เหมือนกันอ่ะ คืออันนึงเเสดงเเบบนึง อันนึงก็แบบนึง เอาแแบบเดียวนะ"*
> *"ตั้งค่า เกี่ยวกับ เอาให้เหมือนรายละเอียดเว้บ คือมีปุ่มกลับ"*

เดิม **ตั้งค่า = หน้าต่างซ้อนเลื่อนขึ้นจากล่าง** · **เกี่ยวกับ = หน้าเต็มจอมีปุ่มกลับ**
ทั้งที่ปุ่มสองอันอยู่ข้างกันบนหัวเว็บและเป็นของประเภทเดียวกัน

**เปลี่ยนตั้งค่าเป็นหน้าเต็มจอ** ตามที่พี่กันสั่ง

🚨 **ต้องเป็น "แทนที่" ไม่ใช่ "วาดเพิ่ม"**
วาดคู่กับหน้าบันทึกแล้วของสองหน้าอยู่ใน DOM พร้อมกัน ปุ่มซ้ำ
(จับได้ตอนตัวตรวจนับชิปได้ 10 อันแทนที่จะเป็น 5)
🚨 **ต้องเอาออกจาก `anyModalOpen`** ไม่งั้นฉากหลังถูกล็อกทั้งที่ไม่มีอะไรซ้อน
🚨 **`recordNarrow` ต้องเช็ค `!settingsOpen`** ไม่งั้นแถบบันทึกลอยทับ
