## 1. บังคับเลือก รพ.สต. ต้นทาง

**ด่านกลางตัวเดียว** `handlers/record.js` → `app.pcuSiteMissing()` ใช้ทั้ง `askSave` และ `save`
(ต้องมีทั้งสองที่ เพราะเส้นทาง "ลองส่งใหม่" หลังเน็ตหลุดข้าม `askSave` ไปเลย)

| เงื่อนไข | ผล |
|---|---|
| รายชื่อ รพ.สต. ในระบบว่างเปล่า | **ปล่อยผ่าน** ไม่มีตัวเลือกให้กดแล้วยังบังคับ = บันทึกงานประจำวันไม่ได้เลย |
| มีรายชื่อ + แหล่งที่มาเป็น รพ.สต. + ไม่ได้เลือกแห่ง | **กั้น** |
| มีแถวที่ติดธง รพ.สต. ไว้ แม้ตอนนี้เลือก OPD อยู่ | **กั้น** |

🚨 **ต้องตรวจถึงระดับแถว** แถวเก็บ `source` ไว้ตั้งแต่ตอนกดเพิ่ม (คนไข้ 2 คนในล็อตเดียวใช้คนละแหล่งได้)
เพิ่มยาตอนเลือก รพ.สต. ไว้แล้วสลับไป OPD ก่อนกดส่ง = แถวนั้นยังเป็น รพ.สต. ที่ไม่มีชื่อแห่งติดไปด้วย

ป้ายในช่องเปลี่ยนเป็น **"ต้องเลือกก่อนบันทึก"** เฉพาะตอนถูกเรียกจากหน้าบันทึก
(`renderPcuField(V, { required: true })`) หน้าต่างแก้ไขล็อตยังเป็น "ยังไม่ได้เลือก" ตามเดิม เพราะพี่กันไม่ได้สั่ง

🚨 **โหมดดูตัวอย่างต้องมีรายชื่อ รพ.สต. ด้วย** (`enterDemo` ส่ง `DEMO_PCU`)
ไม่งั้นเปิดโหมดนี้แล้วช่องขึ้นว่า "ยังไม่ได้ตั้งรายชื่อ" = ไม่มีทางเห็นการบังคับที่เพิ่งทำ (กฎข้อ 3.12)

**ทดสอบ 8 เคส ผ่านทั้งหมด** ยิงเข้าฟังก์ชันจริงในหน้าเว็บผ่าน React fiber

## 2. หน้าผลบันทึกสำเร็จเต็มจอ

ก่อนลงมือทำมอคอัป 3 แบบให้พี่กันกดเลือก (ก เรียบตาม DRP · ข มีการ์ดสรุป · ค มีรายการยาทั้งล็อต)
พี่กันเลือก **แบบ ข**

ก่อนออกแบบได้ไปโคลนโค้ด ME-DRP มาดูของจริง (`components/views/ResultOverlay.tsx`)
ไม่ได้เดาจากคำอธิบาย

| ส่วน | เนื้อหา |
|---|---|
| เลข Lot | ชิปตัวใหญ่ — เลขเดียวที่ใช้ตามล็อตกลับมาได้ และต้องเขียนคู่กับถุงยาจริง |
| การ์ดสรุป | ใช้ต่อได้ / ทำลาย / รายการยา / ผู้บันทึก / แหล่งที่มาพร้อม รพ.สต. / วันที่ |
| ปุ่ม | ตกลง · ดูใบสรุป Lot นี้ |

**ทำไมต้องมี** — ของเดิมบอกผลด้วยข้อความเด้งที่หายเองใน 2 วินาที เลข Lot จึงหายไปด้วย

🚨 **ยอดคิดจาก `sending` ไม่ใช่ `st.rows`** ระหว่างรอเซิร์ฟเวอร์ตอบเภสัชกรพิมพ์ยาเพิ่มได้
🚨 **`state.result` ห้าม persist** เปิดเว็บใหม่ต้องไม่เจอหน้าผลของล็อตเมื่อวานค้าง
🚨 **ปุ่มใบสรุปส่งแค่หัวล็อตให้ `openLotSlip` ตัวเดิม** แล้วมันไปดึงแถวจริงจากฐานเอง
ยอดบนใบจึงมาจากข้อมูลที่เข้าฐานแล้ว ไม่ใช่ตัวเลขที่ค้างในเครื่อง (กฎเดิมของใบสรุป)

**ทดสอบ** กดปุ่มใบสรุปในโหมดดูตัวอย่าง ใบเปิดจริง เลขที่เอกสาร `ยค. L690828-03` รายการครบ 6 แถว
มีปุ่มพิมพ์กับบันทึก PDF · กด Esc หนึ่งครั้งปิดเฉพาะใบ หน้าผลยังอยู่ (ลำดับชั้นถูก)

## 3. ของค้างต้องส่งเองจนกว่าจะสำเร็จ (4 ข้อที่พี่กันเคาะ)

### สิ่งที่มีอยู่แล้วก่อนวันนี้

ร่างเก็บลง localStorage ทุกครั้งที่แตะ · ส่งซ้ำเมื่อได้สัญญาณเน็ตกลับมาและตอนกลับเข้าแท็บ
· ใช้ `batchId` เดิมเสมอ จึงไม่มีทางได้ข้อมูลซ้ำ

### สิ่งที่เติมเข้าไป

**① ลองเองเป็นระยะ ถอยห่างขึ้น** `RETRY_WAITS = [20, 40, 80, 160, 300]` วินาที
ค้างที่ 5 นาทีไปเรื่อย ๆ **ไม่หยุดเอง** — หยุดเมื่อไหร่แปลว่าต้องมีคนมากด ซึ่งคือสิ่งที่เลี่ยงอยู่

🚨 **ทำไมรอสัญญาณ "เน็ตกลับมา" อย่างเดียวไม่พอ** เบราว์เซอร์ยิงสัญญาณนั้นเมื่อเครื่อง
**หลุดจากเครือข่าย** เท่านั้น แต่อาการจริงในโรงพยาบาลคือไวไฟครบทุกขีดแต่ออกเน็ตไม่ได้
เครื่องคิดว่าตัวเองออนไลน์ตลอด ไม่มีสัญญาณไหนยิงเลย ของค้างเงียบข้ามวันได้

**② ปิดแท็บแล้วเปิดใหม่ต้องยังรู้ตัว** เก็บ `saveFailed` · `saveError` · `failedBy` ลง localStorage
แล้วกู้กลับตอนเปิดเว็บ พร้อมลองส่งให้เองทันที

🚨🔴 **`failedBy` ห้ามเอาไปเติมในช่องผู้บันทึกเด็ดขาด** (กฎข้อ 3.24 ยังอยู่ครบ)
ช่องผู้บันทึกถูกล้างทุกครั้งที่เปิดเว็บโดยตั้งใจ เพราะคอมห้องยาเป็นเครื่องกลาง
แต่ล็อตที่ค้าง**ถูกเซ็นไปแล้ว**ตั้งแต่กดส่งครั้งแรก การส่งซ้ำคือส่งของเดิมที่เซ็นไว้
`save()` จึงใช้ `const by = st.recorder || (st.saveFailed ? st.failedBy : '')`
ถ้าไม่ทำแบบนี้ ระบบจะส่งของค้างเองไม่ได้เลยหลังเปิดเว็บใหม่ ต้องมีคนมากดทุกครั้ง

**③ เตือนก่อนปิดหน้าต่าง** เฉพาะตอนส่งไม่สำเร็จจริง ๆ
🚨 ไม่ใช่ทุกครั้งที่มีร่างค้าง — ร่างที่ยังกรอกไม่เสร็จเป็นเรื่องปกติของงานประจำวัน เตือนทุกครั้งแล้วคนจะเลิกอ่าน

**④ หน้าส่งไม่สำเร็จเต็มจอ** ตอบ 3 คำถามที่คนใช้ถามในใจ

| คำถาม | หน้าตอบว่า |
|---|---|
| ของหายไหม | ไม่หาย เก็บอยู่ในเครื่องนี้แล้ว ยังไม่ขึ้นระบบส่วนกลาง |
| ระบบทำอะไรอยู่ | **นับถอยหลังจริงทุกวินาที** จนกว่าจะลองส่งเองครั้งถัดไป + ลองไปแล้วกี่ครั้ง |
| ต้องทำอะไรต่อ | ส่งอีกครั้งเดี๋ยวนี้ · หรือเก็บไว้ส่งทีหลัง |

🚨 **ข้อความลอย ๆ ว่า "ระบบจะลองใหม่ให้" ใช้ไม่ได้** ไม่มีอะไรพิสูจน์ว่าระบบยังทำงานอยู่
คนจะไม่เชื่อแล้วกดเองรัว ๆ

🚨 **ระบบส่งเองห้ามเด้งหน้าเต็มจอ ทั้งตอนสำเร็จและตอนล้ม** — `app.save({ auto: true })`
เภสัชกรอาจกำลังกรอกล็อตถัดไป และถ้าล้มซ้ำทุก 5 นาทีจะกลายเป็นจอเด้งทั้งวันจนคนเลิกอ่าน
⚠️ `app.save` ถูกผูกเป็นตัวรับการกดปุ่มด้วย จึงได้ event object มาเป็น `opts`
**ต้องเทียบ `opts.auto === true` เท่านั้น**

🚨 **นาฬิกาถอยหลังเดินเฉพาะตอนหน้านั้นเปิดอยู่** เว็บเปิดค้างทั้งวัน ตัวจับเวลาที่เดินเปล่า = วาดจอทิ้งวันละหมื่นรอบ

🚨 **ปุ่มคู่บนหน้าผลห้ามใส่คลาส `.tap`** ห่างกัน 10px ส่วน `.tap` ขยายพื้นที่กดด้านละ 11px
= เล็ง "ตกลง" แล้วโดน "ดูใบสรุป" (กฎข้อ 3.55) ปุ่มสูง 50/44 ผ่านเกณฑ์อยู่แล้ว

## 4. วิธีทดสอบบนเครื่องคลาว

เครื่องคลาว**ไม่มีกุญแจฐานข้อมูล** จึงกดบันทึกจนสุดทางไม่ได้ ใช้ 3 ท่าแทน

| ท่า | ใช้ตรวจอะไร |
|---|---|
| ยิงเข้าฟังก์ชันจริงในหน้าเว็บผ่าน React fiber | ตรรกะการกั้น · จังหวะถอยห่าง · การล้างคิว |
| ดักคำขอแล้วตอบแทนเซิร์ฟเวอร์ (puppeteer intercept) | ระบบส่งเองสำเร็จ vs คนกดเอง ให้ผลต่างกันไหม |
| ถ่ายภาพหน้าจริงทั้งจอคอมและจอมือถือ | หน้าตา · ปุ่มตกขอบไหม · สีตอนเอาเมาส์ชี้ |

**ผลที่วัดได้จริง**
- จังหวะลองซ้ำ 20 / 40 / 80 / 160 / 300 / 300 / 300 วินาที
- เปิดเว็บใหม่ทั้งที่มีของค้าง: รู้ตัวว่าค้าง · กู้ยาครบ · `batchId` เดิมอยู่ · ลองส่งเองไปแล้ว 1 ครั้ง
  · จำผู้เซ็นไว้ · **ช่องผู้บันทึกยังว่างเปล่า**
- เตือนก่อนปิดหน้าต่าง: มีของค้าง = กั้น · ไม่มีของค้าง = ไม่กั้น
- ระบบส่งเองสำเร็จ → หน้าเต็มจอไม่เด้ง · หน้าที่เปิดค้างปิดเอง · ล้างคิวและชื่อผู้เซ็นค้างครบ
- ปุ่ม 350×50 กับ 350×44 ห่างกัน 10px ไม่มีคลาส tap · สีตอนชี้อยู่ในโทนของปุ่มทั้งคู่

**คำสั่งที่ใช้ได้บนเครื่องคลาว**
```bash
npm install && npm run dev                    # ไม่มี .env.local ก็รันได้ แค่ API ตอบ 500
/opt/pw-browsers/chromium                     # Chrome สำหรับ puppeteer-core
```
⚠️ `scripts/ui-check.mjs` ใช้บนคลาวไม่ได้ตรง ๆ เพราะ `CHROME_PATHS` ไม่มีพาธของลินุกซ์
รอบนี้เขียนสคริปต์ชั่วคราวไว้นอก repo แทน

## 6. เรื่องที่ยังค้าง

- **พี่กันยังไม่ได้เทสบนเครื่องตัวเอง** เส้นทางที่ต่อฐานข้อมูลจริงทั้งหมดยังไม่เคยถูกกดจริง
  โดยเฉพาะ กดบันทึก → หน้าผลเด้ง → กดตกลง → กลับหน้ากรอก
- **รายการ Lot ในโหมดดูตัวอย่างไม่มีแหล่งที่มา** (`lotsMap` ใน `lib/demo.js` ไม่มี `src`/`pcuSite`)
  ใบสรุปในโหมดตัวอย่างจึงขึ้นว่า "ไม่ระบุ" · ของจริงไม่กระทบ · แจ้งพี่กันแล้ว รอเคาะว่าจะแก้ไหม
- **หน้าต่างแก้ไขล็อตยังไม่บังคับเลือก รพ.สต.** ทำเฉพาะหน้าบันทึกตามที่สั่ง
- `package-lock.json` ถูก npm บนคลาวแก้เอง (ลบบรรทัด `libc` 167 บรรทัด) — คืนกลับแล้ว ไม่ได้ commit
