- เลขล็อตติดไปทุกแถว ค้นด้วยเลขล็อตได้ และแยกดูรายล็อตได้

## 2.2 เซ็นชื่อก่อนปิดล็อต 🆕

กดปุ่ม "บันทึก N รายการ" → **ไม่ส่งทันที** เด้งหน้าต่างให้เลือกชื่อผู้บันทึกก่อน

- รายชื่อ **16 คน** ก๊อปมาจากโปรเจกต์ ME-DRP (`lib/constants.ts` → `REPORTERS`)
  **เก็บสำเนาไว้ในโปรเจกต์นี้เอง ไม่ดึงข้ามเว็บตอนใช้งาน** — 2 เว็บแยกกัน ถ้าผูกกันวันหน้าแก้ที่หนึ่งอีกที่พังตาม
- **จำคนล่าสุดไว้** ครั้งต่อไปติ๊กไว้ให้แล้ว กดยืนยันอย่างเดียว = เพิ่มแค่ 1 คลิก

- ชื่อติดไปทุกแถวในล็อต โชว์ในหน้าประวัติ และค้นด้วยชื่อคนได้

## 2.5 ราคา 4 ตำแหน่งทศนิยม 🆕

**ตอนนี้เก็บครบ 4 ตำแหน่ง** หน้าจอยังโชว์ 2 ตำแหน่งเหมือนเดิม

## 2.6 ตีราคาย้อนหลัง 🆕

**ปัญหาเดิม:** ราคาถูกแช่ไว้ในแถวตอนบันทึก ถ้าบันทึกไปตอนราคายังเป็น 0
แถวนั้นจะมูลค่า 0 **ตลอดกาล** ไปใส่ราคาทีหลังก็ไม่ช่วย ต้องลบทิ้งแล้วกรอกใหม่

**ทางแก้:** ใส่ราคายาแล้วระบบถามว่า "เจอ 34 รายการเก่าของยานี้ที่ยังไม่มีมูลค่า จะเติมราคาย้อนหลังไหม"

🚨 **เติมเฉพาะแถวที่ราคาเป็น 0 เท่านั้น ไม่ทับแถวที่มีราคาอยู่แล้วเด็ดขาด**
เป็นการ "เติมของที่ยังว่าง" ไม่ใช่ "เขียนทับของเก่า" → **กฎแช่ราคายังอยู่ครบ**
มีช่องบันทึกไว้ด้วยว่าแถวไหนถูกตีราคาย้อนหลัง เมื่อไหร่ โดยใคร → ตอบผู้ตรวจได้

# ส่วนที่ 3 — บั๊กที่ยังไม่ได้แก้ (21 จุด)

## 3.1 ร้ายแรง 🔴

### 1. มือถือ — ชื่อยาล้นแถว ทับปุ่ม
วัดจริงที่จอกว้าง 360px คอลัมน์ชื่อยาเหลือ **83px**
"Amoxicillin + Clavulanic acid 875 + 125 mg" แตกเป็น **4 บรรทัด สูง 112px**
ถ้ามูลค่าเป็นหลักล้าน คอลัมน์ชื่อเหลือ **62px** และคำยาวสุด **ล้นออกไปทับป้ายใช้ต่อ/ทำลาย**

**สาเหตุ:** ฝั่งขวาเป็นก้อนตายตัวที่ไม่ยอมหด (ป้าย 88px + ช่องมูลค่า 74px + ปุ่มลบ 22px = 200px จากแถวที่มีแค่ 296px) และชื่อยาไม่มีการตัดด้วยจุดไข่ปลา
มอคอัปพรีวิวที่ 430px และใช้ชื่อยาสั้นๆ ปัญหาเลยไม่โผล่

**ทางแก้:** บนมือถือแยกชื่อยาขึ้นบรรทัดบนเต็มความกว้าง ปุ่มกับตัวเลขลงบรรทัดล่าง

### 2. มือถือ — ป๊อปอัปใส่จำนวนโดนแป้นพิมพ์บัง
แตะยา → ป๊อปอัปเปิด → โฟกัสช่องจำนวนอัตโนมัติ → แป้นพิมพ์เด้ง
→ **ปุ่ม "เพิ่ม" กับปุ่มลัด 10/30/60/90 หายใต้แป้นพิมพ์**
→ ส่วนเดียวที่ยังกดได้คือพื้นหลัง ซึ่งกดแล้ว **ปิดป๊อปอัปทิ้ง จำนวนที่พิมพ์หายหมด**
→ บน iPhone แป้นตัวเลขไม่มีปุ่ม Enter ทางออกด้วยคีย์บอร์ดจึงใช้ไม่ได้

**ทางแก้:** ตั้งค่าให้ป๊อปอัปเลื่อนหนีแป้นพิมพ์ + เพิ่มปุ่มปิด ✕ + กดพื้นหลังไม่ปิด
⚠️ **ข้อนี้ต้องเทสบนมือถือจริงถึงจะยืนยันได้**

### 3. คอม — จอ 960–1100px คอลัมน์ชื่อยาเหลือ 34px
วัดจริงที่ 960px คอลัมน์ "ยา" หน้าบันทึกกว้าง **34px** หน้าประวัติ **62px**
แค่ "Metformin 500 mg" ก็ตัดเป็น 3 บรรทัดแล้ว ถ้าเป็นชื่อยาว ตารางพังเลย
ที่ 1366px ขึ้นไปถึงจะปกติ

**ทางแก้:** ขยับจุดตัดหน้าคอมจาก 960 เป็น 1180-1280 (แก้ที่เดียว) หรือใส่ความกว้างขั้นต่ำ + ตัดด้วยจุดไข่ปลา + หดคอลัมน์ตรึงลง

### 4. สวิตช์ "มุมมอง" ทับปุ่มแก้/ลบ
สวิตช์ที่เพิ่งใส่กลับมา ลอยทับปุ่ม แก้/ลบ ของแถวล่างสุดในตารางประวัติ
เกิดกับทุกความกว้างต่ำกว่าราว 1700px = **จอทำงานจริงทุกเครื่อง**
และ **ยังลอยเด่นอยู่บนฉากมืดตอนหน้าต่างยืนยันลบเปิด**

**ทางแก้:** ย้ายไปมุมซ้ายล่าง หรือซ่อนตอนมีหน้าต่างเปิด + เว้นระยะล่างให้พื้นที่เลื่อน

### 5. ยาราคา 0 ยังบันทึกได้ ไม่มีอะไรกั้น
ตอนนี้ยา 417 ตัวราคา 0 หมด · ป้ายเตือนมีแค่ตัวหนังสือแดงเล็กๆ ในผลค้นหา
พอกดเลือกแล้วป้ายหายไป ในป๊อปอัปเห็นแค่ `0.00 ฿ / เม็ด` ซึ่ง **ดูเหมือนยังโหลดไม่เสร็จมากกว่าดูเหมือนคำเตือน**
ปุ่มบันทึกก็ไม่บอกว่ามีกี่รายการที่มูลค่า 0

**ทางแก้:** ยาราคา 0 กดเพิ่มไม่ได้ + ปุ่มลัดไปหน้าตั้งราคา + ถ้ามีปนอยู่ ปุ่มบันทึกขึ้นแถบส้มเตือน

### 6. ไม่มีล็อกอิน + API เปิดโล่ง
พอขึ้นเว็บจริง **ใครมีลิงก์ก็ยิงคำสั่งลบข้อมูลทั้งปีงบได้ในไม่กี่วินาที**
และ **HN คือข้อมูลผู้ป่วย** อยู่บนเว็บที่ไม่มีรหัสผ่าน (เข้าข่ายที่โรงพยาบาลต้องอธิบายได้ตาม PDPA)

**สถานะ:** ถังขยะทำแล้ว (กู้คืนได้) · คนบันทึกทำแล้ว (รู้ว่าใครทำ) · **เหลือรหัสผ่านร่วม 1 ชั้น ที่พี่กันเคาะว่าเอา**

## 3.3 เล็กน้อย 🟡

- **ลบราคาจนว่างแล้วบันทึก = ตั้งเป็น 0 เงียบ ๆ** — เผลอกด Backspace ค้างแล้วบันทึก ยาตัวนั้นกลายเป็น "ยังไม่ใส่ราคา" ทันที
- **ราคาที่แก้ค้างไว้ไม่ถูกล้างตอนออกจากหน้าจัดการราคา** — กลับเข้ามาวันหลังเจอ "บันทึกราคา 3 รายการ" ค้างอยู่ ไม่รู้ว่าแก้อะไรไว้
- **ชื่อห้องยาบันทึกไม่สำเร็จแล้วย้อนผิดตัวอักษร** — เด้งกลับเป็น "ห้องยาผู้ป่วยนอ" (ขาดตัวสุดท้าย) แทนที่จะเป็นชื่อเดิมก่อนพิมพ์
- **localStorage เต็มหรือถูกปิด ไม่มีใครบอก** — โหมดส่วนตัวของ Safari จะเก็บร่างไม่ได้ แต่ระบบเงียบ พอรีเฟรชข้อมูลหายหมด
- **การ์ดยาสูตรผสมแยกชื่อผิดจุด** — `Amoxicillin + Clavulanic acid 875 +` / `125 mg` (มี `+` ห้อยท้ายบรรทัดบน)
- **ข้อความเด้งทับตัวเลขบนมือถือ** — ค่า `bottom:96px` ของมอคอัปไม่พอ เมื่อแถบบันทึกสูงราว 200px
- **สี "—" ในกราฟจางเกินอ่านไม่ออก** — คอนทราสต์ 1.8:1 จากเกณฑ์ 4.5:1 · ธีมเข้ม 2.7:1
- ✅ **ปุ่มเขียน "Export Excel" แต่ได้ไฟล์ `.csv`** — แก้แล้วโดยเติมหัวไฟล์ + ยอดรวม ให้ผู้บริหารเปิดแล้วเข้าใจทันที
- **ช่องวันที่โชว์ ค.ศ. ขัดกับทั้งเว็บที่เป็น พ.ศ.** — `<input type="date">` เป็นของเบราว์เซอร์ บังคับ ค.ศ. เสมอ (✅ ไฟล์ Export แก้เป็น พ.ศ. แล้ว)
- **ยาซ้ำในรายการไม่เตือน** — โดนขัดจังหวะแล้วกรอกยาตัวเดิมซ้ำ ระบบสร้าง 2 แถวเงียบ ๆ
- **ร่างค้างข้ามกะไม่มีวันหมดอายุ + ไม่มีปุ่มล้างรายการทั้งหมด** — เวรเช้าทิ้งของค้าง เวรบ่ายเปิดมาเจอ ไม่รู้ว่าของใคร · ต้องกด ✕ ทีละแถว
- **กราฟปัดหลักพัน** — 3,499 กับ 3,500 แสดงเป็น "3k" กับ "4k" ผู้บริหารบวกจากกราฟแล้วไม่ตรงยอดรวม
- ✅ **เลข 60 เขียนไว้ 2 ที่** — แก้แล้วตอนทำปุ่ม "ดูเพิ่ม" (ฝั่งจอนับจากจำนวนแถวจริง)
- **ยังไม่มี security headers** — `next.config.js` มีแค่ `reactStrictMode` · โปรเจกต์พี่น้อง (TB Dashboard) ใส่ CSP ไว้แล้ว ควรยกมาใช้แบบเดียวกัน
- **แถบเมนูไม่มีความกว้างสูงสุดบนจอใหญ่** — จอ 1920px โลโก้ชิดซ้ายสุด วันที่ชิดขวาสุด ไม่ตรงแนวกับเนื้อหาที่คุมไว้ 1400px
- **กราฟ 12 เดือนบนมือถือป้ายตัวเลขทับกัน** — คอลัมน์กว้าง 21px แต่ป้าย `1.23M` กว้าง 25px

# ส่วนที่ 4 — ⭐ ข้อเสนอมุมคลังสินค้า

> พี่กันสั่งให้มองเว็บนี้เป็น **ระบบคลังสินค้า** แล้วเสนอสิ่งที่ระบบคลังจริงมี

ยาที่ผู้ป่วยคืนมา ในทางคลังคือ **"ของรับคืน" (Return Goods)** ที่ต้องผ่านการตรวจสภาพ
ก่อนตัดสินว่าเอากลับเข้าคลังได้ (`ใช้ต่อได้`) หรือต้องตัดจำหน่าย (`ทำลาย`)
เทียบกับระบบคลังมาตรฐานแล้ว เว็บนี้ยังขาดของสำคัญหลายอย่าง

## 🥇 อันดับ 1 — วันหมดอายุ (สำคัญที่สุด)

**ปัญหา:** ตอนนี้ระบบบอกว่ายา 90 เม็ดนี้ "ใช้ต่อได้ ประหยัด 450 บาท"
แต่ **ไม่รู้ว่ายาหมดอายุเมื่อไหร่** → เอากลับเข้าคลังจริงไม่ได้ถ้าเหลืออายุไม่ถึงเกณฑ์

ในทางคลัง ของที่รับคืนแล้วเหลืออายุน้อยกว่าเกณฑ์ (มักใช้ 6 เดือน หรือ 1 ใน 3 ของอายุเดิม)
**ต้องตัดจำหน่ายทันที** ไม่นับเป็นของที่กู้คืนได้

**ผลกระทบถ้าไม่มี:** ตัวเลข "ประหยัดได้" ที่รายงานผู้บริหาร **สูงเกินจริง**
เพราะรวมยาที่จริงๆ เอากลับไปใช้ไม่ได้

**เสนอ:** เพิ่มช่องวันหมดอายุตอนกดเพิ่มยา (ไม่บังคับ แต่ถ้ากรอกจะได้ประโยชน์เยอะ)
→ ระบบเตือนเองถ้าเหลือน้อยกว่าเกณฑ์ → แนะนำให้เลือก "ทำลาย"
→ หน้าสรุปแยก **"ประหยัดได้จริง"** ออกจาก **"คืนมาแต่ใช้ไม่ได้"**

## 🥈 อันดับ 2 — สถานะรอตรวจสภาพ (Quarantine)

**ปัญหา:** ตอนนี้มี 2 สถานะเท่านั้น — ใช้ต่อได้ / ทำลาย
แต่ในความเป็นจริง ตอนรับคืนหน้าเคาน์เตอร์ **เภสัชกรยังไม่ได้ตรวจสภาพยาละเอียด**
ต้องรีบรับไว้ก่อนเพราะคนไข้รออยู่

ระบบคลังจริงจึงมีสถานะกลางชื่อ **"รอตรวจสอบ" (Quarantine)** — ของเข้ามาแล้วแต่ยังไม่ตัดสิน

**เสนอ:** เพิ่มสถานะที่ 3 **"รอตรวจสภาพ"** เป็นค่าเริ่มต้น
→ รับคืนเร็ว ตรวจทีหลังตอนว่าง → หน้าประวัติมีปุ่มเปลี่ยนเป็น ใช้ต่อ/ทำลาย
→ หน้าสรุปมีตัวเลข "ค้างรอตรวจ N รายการ" เตือนไม่ให้ลืม

## 🥉 อันดับ 3 — นำกลับเข้าคลังแล้วหรือยัง

**ปัญหา:** ยาที่ติดสถานะ "ใช้ต่อได้" ถูกนับเป็นเงินที่ประหยัดได้ทันที
แต่จริงๆ **ยังเป็นแค่ตัวเลขบนกระดาษ** จนกว่าจะมีคนเอายานั้นกลับขึ้นชั้นจริง

ในทางคลังนี่คือ 2 ขั้นตอนแยกกัน — **ตัดสินใจ (Disposition)** กับ **เคลื่อนย้ายจริง (Put-away)**

**เสนอ:** เพิ่มติ๊ก **"นำกลับเข้าคลังแล้ว"** พร้อมวันที่และคนทำ
→ หน้าสรุปแยก "ประหยัดตามบันทึก" กับ "นำกลับเข้าคลังจริงแล้ว"
→ ตอบผู้ตรวจได้ว่าเงินที่ประหยัดนั้นเป็นของจริง ไม่ใช่ตัวเลขลอย

## อันดับ 4 — ใบสรุปล็อต (พิมพ์ออกมาแปะได้)

ตอนนี้มีเลขล็อตแล้ว (`L690805-01`) แต่ยังพิมพ์ออกมาไม่ได้

**เสนอ:** ปุ่มพิมพ์ใบสรุปล็อต 1 หน้า — เลขล็อต · วันที่ · ผู้บันทึก · รายการยา · ยอดรวม · ช่องเซ็นชื่อผู้ตรวจสอบ
เอาไปแปะกับถุงยาที่รอตรวจ หรือเก็บเข้าแฟ้มเป็นหลักฐาน

## อันดับ 5 — ปิดงวด (ล็อกไม่ให้แก้ย้อนหลัง)

**ปัญหา:** ตอนนี้แก้รายการเก่าได้ตลอด แม้เป็นเดือนที่รายงานผู้บริหารไปแล้ว
→ ตัวเลขที่รายงานไปกับตัวเลขในระบบ **ไม่ตรงกัน** โดยไม่มีใครรู้

**เสนอ:** ปุ่ม "ปิดงวดเดือน" — ปิดแล้วแก้ไม่ได้ ต้องเปิดใหม่ก่อน (มีบันทึกว่าใครเปิด)
เป็นมาตรฐานของทุกระบบบัญชี/คลัง

## อันดับ 6 — ยิงบาร์โค้ดแทนพิมพ์ชื่อ

ซองยาโรงพยาบาลมีบาร์โค้ดอยู่แล้ว · ต่อเครื่องอ่านบาร์โค้ด (ราคาไม่กี่ร้อย เสียบ USB ใช้ได้เลย)
→ ยิงบาร์โค้ด = ได้ยาตัวนั้นทันที ไม่ต้องพิมพ์ ไม่มีทางเลือกผิดความแรง
→ **แก้ปัญหาข้อ 7 ในส่วนที่ 3 ได้ในตัว** (Enter เลือกผลแรกผิดความแรง)

## อันดับ 7 — ล็อตของผู้ผลิต (Manufacturer Lot)

ถ้าเกิดกรณีเรียกคืนยา (Drug Recall) จากบริษัท จะตามได้ว่ายาล็อตนั้นเคยถูกคืนมาบ้างไหม
ตอนนี้ตามไม่ได้เลย · **เสนอเป็นช่องไม่บังคับ** กรอกเมื่อจำเป็น

## อันดับ 8 — ตัวชี้วัดแบบคลัง

ตอนนี้มีแค่ "ประหยัดได้เท่าไร" · ระบบคลังจริงดูตัวเลขพวกนี้ด้วย

# ส่วนที่ 6 — สิ่งที่ทำไว้ดีแล้ว ไม่ต้องแตะ

ทีมตรวจยืนยันตรงกันทั้ง 5 ชุด

- **🏆 กฎแช่ราคาทำถูกต้อง 100%** — ไล่ครบทุกทางเข้าออกแล้ว ไม่มีรูรั่ว
  การแก้ไขรายการเก่าปิดตายไม่ให้แตะราคา · หน้าประวัติดึงราคาที่แช่ไว้ในแถวมาใช้จริง
  ⚠️ **กับดัก:** ถ้าวันหน้ามีใครเปลี่ยนค่า `ignoreDuplicates` เป็น `false` ราคาที่แช่ไว้จะถูกทับทันทีโดยไม่มีอะไรเตือน — เขียนกำกับไว้ในโค้ดแล้ว
- **ตัวเลขเงินไม่เพี้ยน** — การคำนวณในเบราว์เซอร์กับในฐานข้อมูลให้ผลตรงกันเสมอ · ยอดหน้าสรุปกับหน้าประวัติคิดจากสูตรเดียวกัน
- **กติกาการนับตรงมอคอัปเป๊ะ** — `byDrug`/`byMonth` เฉพาะใช้ต่อได้ · `bySrc` ทั้งสองแบบ
- **ปีงบไทย ต.ค.–ก.ย. คำนวณถูก** — 30 ก.ย. กับ 1 ต.ค. อยู่คนละปีงบจริง · ใช้นาฬิกาไทยไม่ใช่ UTC ทั้งสองฝั่ง
- **ตัวอักษร BOM ในไฟล์ส่งออกใส่ถูก** — ภาษาไทยเปิดใน Excel ไม่เป็นตัวยึกยือ (ตรวจถึงระดับไบต์แล้ว)
- **การกันบันทึกซ้ำตอนเน็ตหลุด** — แข็งแรงมาก
- **กุญแจฐานข้อมูลอยู่ฝั่งเซิร์ฟเวอร์ล้วน** — ไม่มี `NEXT_PUBLIC_` แม้แต่ตัวเดียว · เปิด view-source ไม่เจอกุญแจ
- **RLS ปิดตายทั้ง 3 ตาราง** — เปิดไว้โดยไม่มี policy สักข้อ = ปฏิเสธทุกคำขอจากภายนอก
- **ไม่มีเครื่องหมาย `?` ในข้อความบนหน้าเว็บสักจุด** — grep ทั้งโปรเจกต์แล้ว
- **ไม่มี ค่ะ/นะคะ/ครับ ในข้อความ UI · ไม่มี `alert()`/`confirm()` ของเบราว์เซอร์เลย**
- **หน้าต่างยืนยันลบถูกกฎ** — "ยืนยันลบ" ซ้าย "ยกเลิก" ขวา · กดพื้นหลังไม่ปิด
- **ความเร็วการกรอกบนคอมทำได้ตามเป้า** — พิมพ์ → Enter → จำนวน → Enter = **ราว 8 ปุ่ม ไม่ต้องแตะเมาส์ต่อยา 1 ตัว** เร็วกว่าเป้า 15 วินาทีชัดเจน
- **เทียบกับมอคอัปแล้วตรงทุกตัวอักษร** — สี ระยะห่าง ขนาดตัวอักษร ความกว้างคอลัมน์ ลำดับ element

# ภาคผนวก — วิธีตรวจว่ายังใช้ได้จริง

1. `npm run dev` แล้วเปิดบน **Chrome จริง** ไม่ใช่ preview
2. ทดสอบขนาดคอมจริง ~1360px และ **มือถือจริง** — ไม่ใช่แค่ย่อหน้าต่าง
3. **เส้นทางหลัก:** ค้นยา → Enter → ใส่จำนวน → Enter → แถวเพิ่ม → กดบันทึก → **เซ็นชื่อ** → เปิดประวัติเจอ → เปิดสรุปเลขตรงกัน
4. **กรณีขอบ:** ยาไม่มีราคา · ยาชื่อซ้ำ · จำนวน 0/ติดลบ/ทศนิยม · รีเฟรชกลางคัน · ปิดเน็ตแล้วกดบันทึก · 30 ก.ย. กับ 1 ต.ค.
5. **ตรวจกฎแช่ราคา:** บันทึกรายการ → ไปแก้ราคายาตัวนั้น → **ตัวเลขหน้าสรุปต้องไม่ขยับ**
6. **ตรวจถังขยะ:** ลบรายการ → ตัวเลข KPI ต้องลดลง → เปิดถังขยะต้องเจอ → กู้คืนแล้วตัวเลขต้องกลับมา
7. **ตรวจความปลอดภัย:** เปิด view-source ต้องไม่เจอกุญแจ Supabase

---

*รายงานนี้สร้างจากการตรวจโค้ดจริงทั้งโปรเจกต์ + ทดสอบบนเบราว์เซอร์จริง + ตรวจฐานข้อมูลจริง*
*ทุกข้อที่รายงานผ่านการยืนยันแล้วว่าเกิดขึ้นได้จริง ไม่ใช่ทฤษฎี*
