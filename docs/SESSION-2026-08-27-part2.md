## 1. ฟอนต์ Roboto Mono

### กลไก — ยกมาจากเว็บ HCV ทั้งชุด

```
font-family: var(--font-en), var(--font-sarabun), Sarabun, sans-serif
                   ↑ Roboto Mono          ↑ ตัวไทยตกมาใช้ตัวนี้เอง
```

Roboto Mono ไม่มีตัวอักษรไทย เบราว์เซอร์จึงตกมาใช้ Sarabun ให้เอง
**ไม่ต้องเขียนเงื่อนไขแยกภาษาเลยสักบรรทัด**

การสลับทำที่ตัวแปรตัวเดียว `--font-en` · ผู้ใช้เลือกได้ในหน้าตั้งค่า เก็บไว้ในเครื่อง

### 🚨 ใบพิมพ์เอกสารราชการ — พิสูจน์ 2 ชั้น

พี่กันเตือนกลางทาง แคลร์ตรวจทันทีด้วยไฟล์จริง ไม่ใช่แค่อ่านโค้ด

```bash
node scripts/print-check.mjs
node scripts/pdf-font.mjs "out/ใบสรุป-ล็อตล่าสุด.pdf"
```

ผล: ในไฟล์ PDF มีแค่ **THSarabunNew** กับ **THSarabunNew-Bold** ไม่มี Roboto Mono เลย
แปลงเป็นภาพเปิดดูด้วยตาแล้วด้วย — ทั้งใบเป็นฟอนต์ราชการเหมือนเดิม

ปลอดภัยเพราะ `.slip-paper` เขียน `"TH Sarabun New"` ตรง ๆ ใน `@media print`
ไม่ผ่าน `fontify()` และข้างในใบไม่มีการเขียนฟอนต์ในแท็กเลยสักจุด

### 🔴🔴 ชื่อยาไม่เปลี่ยนฟอนต์เลย — พี่กันจับได้เอง

แคลร์เปิดดูทุกหน้าแล้วรายงานว่าเรียบร้อย พี่กันส่งภาพมา 3 ภาพแล้วบอกว่า
*"นี่ขนาดเราให้เธอเปิดดู ยังไม่แก้ชื่อยาอีกนะ ฟอนต์อ่ะะะะ"*

**ต้นเหตุ** — `pages/drugname.jsx` กับ `pages/record.jsx` เขียนฟอนต์ตรง ๆ

```jsx
font-family: var(--font-sarabun),Sarabun,sans-serif   // ❌ Sarabun มาก่อน แล้วชนะ
font-family: var(--font-en),var(--font-sarabun),...   // ✅
```

จุดนี้ไม่ผ่าน `fontify()` เพราะเขียนเป็นชื่อตัวแปรไม่ใช่ชื่อฟอนต์

**และเจอของแถม 12 จุดที่ยังใช้ `var(--font-plex)`** ซึ่งเป็นฟอนต์ไม่มีหัวที่พี่กัน
สั่งเลิกใช้ไปตั้งแต่ 26 ส.ค. 2569 — ความแรง · ตัวย่อ · เปอร์เซ็นต์ · ER/IR
หลุดรอดมาเพราะเหตุผลเดียวกัน · แก้ครบ **14 จุดใน 3 ไฟล์**

### ผลข้างเคียง — ฟอนต์นี้กว้างกว่า Sarabun ราว 15%

| ที่ | อาการ | แก้ |
|---|---|---|
| คอลัมน์วันที่ หน้ารายการ Lot | ตกบรรทัดเป็นสองแถว | 92px → **116px** |
| ตัวเลขใหญ่หน้าสรุป | ล้นออกนอกกรอบ | `clamp(44,9.4vw,132)` → `clamp(38,7.8vw,108)` |
| ชื่อผู้บันทึกหน้าประวัติ | ถูกตัดท้ายเป็น `ภญ. วลัยพรรณ…` | เลิกใช้ ellipsis ให้ขึ้นบรรทัดใหม่ |

**จุด `.` ในคำไทยกว้างขึ้น** (`รพ.สต.` ดูเหมือน `รพ . สต .`) — พี่กันบอกไม่ซีเรียส

### แผงขวาหน้าบันทึกล้น — ไม่ใช่เพราะฟอนต์

วัดด้วยการปิดฟอนต์ชั่วคราวแล้วเทียบ

| | ความสูงที่แผงต้องการ |
|---|---|
| ใช้ Roboto Mono | 663px |
| ใช้ Sarabun | 654px |
| **ฟอนต์ทำให้แย่ลง** | **9px** |

**ต้นเหตุจริงคือจอของพี่กันสูง 641px** ซึ่งเตี้ยกว่าที่แผงต้องการมาแต่ไหนแต่ไร
รีดระยะห่างได้คืน 77px (ล้นจาก 188 เหลือ 111) ที่เหลือยังต้องเลื่อน
ปลอดภัยเพราะปุ่มบันทึกตรึงก้นแผงอยู่แล้ว

🚨 **รีดมากกว่านี้ไม่ได้** — ในไฟล์มีคอมเมนต์เตือนว่าเคยยุบกล่อง "Lot นี้"
แล้วพี่กันเจอบั๊กที่จอ 768 กล่องยุบเหลือ 23px มีแถบเลื่อนจิ๋วข้างใน อ่านไม่ได้เลย

## 2. ตารางหน้ารายการ Lot

### ตรึงหัว 2 ชั้น — ทำเหมือนหน้าประวัติ

```
.lots-head   sticky top:0                  แถบหัวเรื่อง + ค้นหา + ตัวกรอง
.col-head    sticky top:var(--lotshead)    หัวตาราง ติดใต้แถบบนพอดี
```

`--lotshead` มาจาก **ResizeObserver** (`lotsHeadRef`) ตั้งเลขตายตัวไม่ได้
เพราะปุ่มช่วงเวลากับช่องวันที่ขึ้นบรรทัดใหม่เองเมื่อจอแคบ

เทสด้วยการเลื่อน 2 จังหวะ — หัวอยู่ที่ 184px ทั้งสองครั้ง ✓

### 🔴 ช่องไฟหัวคอลัมน์ — พี่กันจับได้ว่าไม่ได้เทส

แคลร์ใส่กฎ `padding:12px` ให้ทั้งหัวและแถว แล้วดูภาพเห็นว่า "ดูมีช่องไฟ" เลยผ่าน

พี่กันทัก: *"เธอใส่ช่องไป 12 แล้ว ดี แต่ลืมอะไรไหม แล้วหัวคอลัมน์ไม่ใส่ให้เราหน่อยเหรอ
บ่งบอกเลยว่าเธอไม่ได้เปิดเทสดู"*

**วัดจริงแล้วหัวได้ 0px ส่วนแถวได้ 12px** — เพราะหัวเขียน `padding` ฝังในแท็ก ซึ่งชนะกฎ CSS

```css
.col-head > span { padding-left: 12px !important; padding-right: 12px !important }
```

### อื่น ๆ

| เปลี่ยนอะไร | เดิม | ใหม่ |
|---|---|---|
| ลูกศรเรียง | `↕` `▲` `▼` 10px | `↑↓` `↑` `↓` 16px / 19px |
| ปุ่มคอลัมน์จัดการ | ชิดขวา | กึ่งกลาง (หัวคอลัมน์ย้ายตาม) |
| ขีดในคอลัมน์ทำลาย | ชิดขวาจนแนบปุ่ม | กึ่งกลางช่อง |
| ผู้บันทึก | 27% แล้วปล่อยว่าง | 24% |
| รายการ · ใช้ต่อได้ | 5% · 7% | 7% · 9% |

## 3. ปุ่ม "เพิ่ม" — บทเรียนเรื่องทำเกินคำสั่ง

พี่กันสั่งสั้น ๆ ว่า "จัดการเรื่องปุ่มเพิ่ม" แคลร์ยกชุด**ครีมอมเหลือง + สั่น**
ของปุ่มบันทึกไปใส่ โดยอ้างกฎ "อะไรที่คล้ายกันต้องทำให้เหมือนกัน"

> *"ปุ่มเพิ่ม ไม่เอาอนิเมชั่น ไม่ได้บอก แล้วปุ่มมันจริง ๆ สีเขียว ก็แค่เปลี่ยนสีเขียวปกติ
>  ปุ่มไหนอนิเมชั่น เราบอกเอง"*

**สองบทเรียนในประโยคเดียว**
1. แอนิเมชันไม่ใช่ของที่ลามไปเองได้ ต้องได้รับคำสั่งรายปุ่ม
2. ปุ่มที่กดไม่ได้ต้องใช้**สีของปุ่มตัวเองที่จางลง** ไม่ใช่ยกสีจากปุ่มอื่นมา

แก้เป็นคลาสใหม่ `.hv-off-green` — เขียวจาง ชี้แล้วเข้มขึ้นนิดเดียว ไม่มีอะไรขยับ
**ตั้งเป็นกฎในสกิล `button-feedback` แล้วทั้ง 2 ที่**

## 4. 🔴 คำสั่งกลุ่ม 3 — แคลร์จดไม่ครบจริง

พี่กันสั่ง: *"เอาประโยคที่เราพิมพ์เรื่องกลุ่ม 3 เอาไปใส่ในนั้นด้วย
เราไม่มั่นใจว่าเธอเก็บคำพูดเราครบไหม"*

กลับไปอ่านข้อความจริงในบทสนทนาแล้วพบว่า **ไม่ครบจริง 2 จุด**

| จุด | ที่แคลร์จดไว้ | ที่พี่กันสั่งจริง |
|---|---|---|
| **ส-7** | อยู่ในรายการ "เคาะแล้ว" | *"อันนี้ต้องคุย ยังไม่เคาะ"* + *"เราคิดไม่ออกแฮะ เธอเสนอมาหน่อย"* — **แคลร์มีการบ้านค้างที่ไม่รู้ตัว** |
| **ก-1** | "แสดงให้รู้ว่าโหลดไม่สำเร็จ" | เป็นแค่ส่วนแรก · ที่สั่งจริงคือ **เก็บข้อมูลไว้ในเครื่องทั้งเว็บ + ลบตอนปิดแท็บ + อัปเดตสดข้ามเครื่อง** |

**และมี ก-2 อยู่ในคำสั่งชุดนั้นด้วย** ซึ่งแคลร์ไม่ได้จดไว้ในรายการกลุ่ม 3 เลย
(ปิดไปแล้วใน v0.11.0.0 จึงไม่เสียหาย แต่แสดงว่าการจดสรุปตกหล่นจริง)

ยกคำสั่งจริงทั้งดุ้นใส่ `docs/AUDIT-STATUS.md` แล้ว **ไม่ตัด ไม่เรียบเรียงใหม่**

🚨 **บทเรียน: คำสั่งของพี่กันต้องเก็บคำต่อคำ** การจดเป็นสรุปสั้น ๆ ทำให้เงื่อนไขหายไป
แล้วรอบหน้าจะทำงานตามที่ตัวเองจดผิด โดยไม่มีใครจับได้
