## 🏆 เรื่องที่ใช้เวลามากที่สุด — หน้าไถลซ้ายขวา

พี่กันบ่นเรื่องเดียวกัน **7 รอบ** ส่งคลิปมา **5 คลิป** กว่าจะจบ

### สิ่งที่ลองแล้วไม่ได้ผล (ได้ผลบนคอมทุกข้อ แต่มือถือไม่ฟังสักข้อ)

| ลองอะไร | ผลบนมือถือจริง |
|---|---|
| แก้ของที่ล้นจอทีละตัว (ท้ายเว็บ 539px · แถบล็อตค้าง 507px) | ยังไถล |
| `overflow-x: hidden` แล้วเปลี่ยนเป็น `clip` ทุกชั้น | ยังไถล |
| `touch-action: pan-y` | ยังไถล |
| `max-width: 100vw` + `@media (max-width: 1179px)` | ยังไถล |
| `position: fixed; inset: 0` ทั้งแอป | ยังไถล (fixed ยึดกับกรอบผัง ไม่ใช่ขอบจอ) |
| วัดขอบจอด้วย `visualViewport` แล้วล็อกความกว้าง | ยังไถล |
| ห้ามซูมทั้งหมด 3 ชั้น | ซูมไม่ได้จริง แต่ยังไถล |

### ✅ สิ่งที่แก้ได้จริง — `_pinLeft`

**เลิกห้าม แล้วดีดตำแหน่งเลื่อนกลับ 0 ทุกครั้ง**

```js
_pinLeft = () => {
  if (!document.body.classList.contains('mrv-mobile')) return;
  const sc = this.scrollRef.current;
  if (sc && sc.scrollLeft !== 0) sc.scrollLeft = 0;
  // + documentElement · body · window
};
document.addEventListener('scroll', this._pinLeft, { passive: true, capture: true });
window.addEventListener('touchmove', this._pinLeft, { passive: true });
window.addEventListener('touchend',  this._pinLeft, { passive: true });
```

- 🚨 **ต้องดัก `touchmove` ด้วย** — บางเบราว์เซอร์ไม่ยิง `scroll` ระหว่างนิ้วยังลากอยู่
- 🚨 **`capture: true` ที่ document** จับกล่องข้างในที่เลื่อนเองได้ทุกตัว
- 🚨 **passive ทั้งหมด** ไม่ได้ห้ามเหตุการณ์ แค่ตั้งค่ากลับ จึงไม่ถ่วงการเลื่อนขึ้นลง
- 🚨 **เช็คคลาสมือถือก่อนเสมอ** ตารางคลังยาฝั่งคอมต้องเลื่อนดูข้าง ๆ ได้จริง

### 🔑 บทเรียนที่ควรทำตั้งแต่รอบแรก

**คำถามของพี่กันคือคำตอบ**

> *"ทำไมกรอบเเสดงค่ายา เเละกรอบปุ่มกด หรือกรอบกดส่งยา ทำไมมันไม่เลื่อน
> ทำไมมเอาระบบนั้นมาไม่ได้"*

คำถามนี้ชี้ตรงจุด — ในคลิป **แถบล่างนิ่งสนิทขณะที่ส่วนบนไถล**
ถ้าทั้งหน้าถูกลาก แถบล่างต้องขยับด้วย พอมันไม่ขยับ = **พื้นที่เลื่อนตัวเดียวที่เลื่อนข้างได้**
ซึ่งดีดกลับด้วยโค้ดได้ ไม่ต้องไปไล่แก้ CSS

**วิธีไล่สาเหตุที่ถูกต้อง — ดูว่าอะไรขยับ อะไรไม่ขยับ ในคลิปเดียวกัน**

| เห็นอะไร | แปลว่า |
|---|---|
| ของนอกพื้นที่เลื่อนนิ่ง + ข้างในไถล | พื้นที่เลื่อนเลื่อนข้างได้ → ดีดกลับด้วยโค้ด |
| ทุกอย่างขยับพร้อมกัน รวมแถบที่อยู่เบราว์เซอร์ | กรอบหน้าเว็บถูกลาก |
| ตัวอักษร**ใหญ่ขึ้น** | ซูมเข้า |
| ตัวอักษร**เล็กลง** เนื้อหาไม่เต็มจอ | เบราว์เซอร์ย่อหน้าเพราะมีของกว้างเกิน |

## 🚨 กฎใหม่ที่พี่กันตั้ง

### ① เอเจนต์ทำอะไรมา ต้องบันทึกลงไฟล์ทุกครั้ง

> *"เเล้วทำไมไม่บันทึกกกกกกก มันเปลืองโทเค่นน ตั้งเป้นกฎเลย
> เอเจ้นทำไรมาต้องบันทึกทุกครั้งงงง เเละเราไม่ให้รันอีก เปลือง"*

รันเอเจนต์ได้ข้อเสนอ 6 ชุด **เล่าในแชทอย่างเดียว ไม่บันทึกลงไฟล์**
พอคุยกันยาวจนบทสนทนาถูกตัด รายการหายทั้งดุ้น ต้องไปขุดจากไฟล์บันทึกแชทกลับมา

→ เพิ่มเป็นข้อ **4.5** ในสกิล `working-with-gun` แล้ว ก๊อปครบ 5 เว็บ
ข้อเสนอ/แผนงาน → `docs/<เรื่อง>-PLAN.md` · ผลตรวจ → `docs/AUDIT-<วันที่>.md`
ต้องมีช่องสถานะ · ต้องบอกว่าแก้ไฟล์ไหน · ข้อที่ผู้ใช้ไม่เลือกห้ามลบทิ้ง

### ② ห้ามซูม (พี่กันยืนยันหลังแคลร์ทักท้วง)

> *"งั้น ห้ามซุม เหมือนจุดที่ตรึงไว้ของปุ่มกดส่งยา เพราะแอปทั่วไป มันซูมไม่ได้ นี่นา"*

แคลร์ทักท้วงเรื่องคนสายตายาว (WCAG 1.4.4) พี่กันยืนยัน → ทำตาม
เว็บนี้ใช้ในห้องยาบนเครื่องเจ้าหน้าที่เอง ไม่ใช่เว็บสาธารณะ
และช่องกรอกทุกช่องถูกบังคับเป็น 16px แล้วซึ่งอ่านง่ายอยู่

### ③ ต้องดูวิดีโอที่ผู้ใช้ส่งมาให้ได้

> *"วิดีโอเราก้ส่งไปแล้ว ไปหาวิธีอ่านวิดีโอมาเดี่ยวนี้ ติดตั้งเดี่ยวนี้"*

ติดตั้ง **ffmpeg** แล้ว (`winget install Gyan.FFmpeg`)
⚠️ ไม่เข้า PATH ของเชลล์ที่เปิดอยู่ ต้องเรียกด้วยที่อยู่เต็ม
ท่าที่ใช้บ่อยสุด — เรียงทั้งคลิปเป็นตารางภาพเดียว

```
ffmpeg -i clip.mp4 -vf "fps=2.5,scale=250:-1,tile=5x3" -frames:v 1 tile.png
```

### ④ ป้ายเลขในชื่อเว็บ (พี่กันคิดเอง)

> *"เธอใส่เลข 1 ในชื่อเว้บหน่อย เราจะได้รู้ว่ามือถือมันเเก้เเล้ว เรากลัวมันไม่อัปเดต"*

ใส่เลขต่อท้ายชื่อเว็บทุกครั้งที่ส่งของใหม่ (1 → 2 → 3 → 4) ผู้ใช้เห็นเลขไหน = ได้โค้ดชุดนั้น
**ตัดคำถาม "โค้ดถึงหรือยัง" ออกจากสมการทันที** ประหยัดเวลาไปได้หลายรอบ
🚨 ลบทิ้งทันทีที่ยืนยันแล้ว
