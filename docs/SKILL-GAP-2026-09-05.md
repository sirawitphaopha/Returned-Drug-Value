# 🔴🔴🔴 ส่วนที่อันตรายที่สุด — สกิลบอกวิธีที่ผิดอยู่ตอนนี้

**อันตรายกว่ากฎที่หายไป** เพราะคนอ่านสกิลจะทำผิดโดยเชื่อว่าทำถูก

| # | สกิลเขียนว่าอะไร | ของจริงคืออะไร | สถานะ |
|---|---|---|---|
| 1 | `working-with-gun` ข้อ 5 แนะนำให้ **เขียนไฟล์ด้วย heredoc** | ME-DRP พิสูจน์แล้วว่าแบ็กสแลชหาย — `/-?\d+/` กลายเป็น `/-?d+/` หาตัวเลขไม่เจอเลย ผ่านทุกตัวตรวจ | ✅ **แก้แล้ว** |
| 2 | `button-feedback` สั่งว่า **ห้ามใช้กฎกลางครอบทุกปุ่ม** | แต่กฎ 16px กันไอโฟนซูมที่ครอบทุกช่อง **เป็นทางที่ถูก** — ไม่มีใครเขียนเส้นแบ่งไว้ | ✅ **แก้แล้ว** |
| 3 | `pharmacy-web-logic` ข้อ 30 บอกให้ส่งซ้ำโดย **ผูกกับสัญญาณ "เน็ตกลับมา"** | บันทึก 29 ส.ค. พิสูจน์แล้วว่าไม่พอ — ไวไฟครบขีดแต่ออกเน็ตไม่ได้ **ไม่มีสัญญาณไหนยิงเลย** · HCV กำลังจะทำตามข้อนี้ | ✅ **แก้แล้ว** |

### ที่แก้ไปแล้ว 2 จุด

**① heredoc** — เปลี่ยนจาก "แนะนำ/ห้ามเครื่องมือ" เป็น **"เขียนอะไรที่มีแบ็กสแลชต้องอ่านไฟล์กลับมาตรวจ"**

เหตุผล — ทดสอบจริงแล้วพบว่า bash heredoc **ไม่ใช่ตัวที่กลืน**

```
① cat > file <<'EOF'            → /-?\d+(?:\.\d+)?/   ครบ
② bash <<'EOF' ที่ข้างในมี echo  → /-?\d+(?:\.\d+)?/   ครบ
③ heredoc ซ้อนสองชั้น            → /-?\d+(?:\.\d+)?/   ครบ
```

ชั้นที่กลืนจริงยังไม่รู้แน่ (น่าจะเป็น PowerShell here-string หรือ `sed`/`node -e` ในสคริปต์)
**ห้ามเครื่องมือผิดตัว = เสียเครื่องมือที่ใช้ได้ แล้วต้นเหตุยังอยู่** จึงเขียนกฎเป็น "ตรวจผลลัพธ์" แทน

**② เส้นแบ่งกฎกลาง** — เขียนหลักตัดสินที่ไม่เคยมีใครเขียนไว้

| ประเภท | ครอบด้วยกฎกลางได้ไหม |
|---|---|
| คำตอบเดียวถูกเสมอ (16px กันซูม · 44px พื้นที่กด) | ✅ ควรครอบ — ครอบของที่จะสร้างวันหน้าด้วย |
| คำตอบขึ้นกับของแต่ละชิ้น (สีตอนชี้ · ขนาดปุ่ม) | ❌ ห้ามครอบ |

**วิธีตัดสิน: "ถ้าครอบทุกตัวด้วยค่าเดียว จะมีตัวไหนแย่ลงไหม"**
